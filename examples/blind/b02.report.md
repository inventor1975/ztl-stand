# b02 — fan selection, two modes (blind test report)

## EXPRESSED FAITHFULLY
- Given: Tamb (mode ranges 15..30 / 30..45 C), P (150 W / 260 W, +-10%, set per mode), K = 32000 +-15%, cp, p, R.
- Catalog of 4 fans: Qmax +-5/5/5/6%, pmax +-8/8/8/10%, price. Noise "+-2" as an absolute range (e.g. 28 -> [26,30]).
- rho = p/(R*(Tamb+273.15)) as a define; Tout = Tamb + dT; the dT = P/(rho*cp*Q) law (with Q substituted, see below).
- Two modes with their own Tout limits (<=40, <=55); noise <= 40 as a top-level requirement; objective = price.
- Units on everything (J*kg^-1*K^-1, Pa*s^2*m^-6, m^3/s); no unit complaint.

## APPROXIMATED
- **Operating flow Q** (the intersection of fan curve and K*Q^2) is NOT expressible (see below). I replaced it by a
  hand-derived rigorous LOWER bound: with g(Q) = pmax*Qmax/(pmax + K*Qmax*Q), the true Q* is a fixed point of the
  decreasing map g, so g(g(...g(Qmax))) with an odd number of g's is <= Q*. I used g^7 (nested defines g0..g7).
  Lower Q -> higher dT -> higher Tout, so this is SAFER (can only refute too much, never earn too much).
  It is not free: g^1 refuted F3 spuriously (Tout bound 58.3 vs true worst 54.97); g^7 is tight enough (54.986).
  The number of iterations (7) was chosen by me, by a hand script, not by the tool.
- "noise" is made a derived quantity (noise == F.noise) only because requirements must be on derived quantities.
- Noise unit left as "" (dBA is not in the unit list); noise is a plain number here.
- Tamb in C used directly in a Kelvin formula via +273.15 (allowed since C is an offset-free difference).

## COULD NOT EXPRESS
- An implicit/operating-point law: "fan curve = system curve, solve for Q". A quadratic in the unknown Q is refused
  ("a nonlinear law must define one derived quantity"). No root-finder, no sqrt, no way to say "Q is the root in (0,Qmax)".
  (Needs: an implicit-equation quantity with a bracket, solved/bounded by the stand.)
- Division by a derived quantity (dT == P/(rho*cp*Q) with Q derived) — I avoided it by substituting Q, so I could
  not test whether it would be accepted.
- Units: dBA / dB-like logarithmic or non-SI units; parentheses in units (J/(kg*K) crashed, see DOC GAPS).
- Nothing about the noise "worst case" beyond a range field; that went in fine.

## TOOL OUTPUT
- Attempt 1 (two laws both defining Dp, quadratic Dp == K*Q*Q): Python traceback (CheckError unknown name 'Dp'),
  not a BRICK ERROR. Attempt 2 (single quadratic law): BRICK ERROR "a nonlinear law must define one derived quantity".
- Attempt 3 (Q lower bound g^1): REFUTED, closest F2, failing mode hot, Tout 55.41 at Tamb 45, P 234 (a violating point).
- Final (g^7), 32 s: verdict EARNED, designs_tried 3 (F4 dropped on noise, 41..45 > 40), design F3
  (Qmax 0.047, pmax 62, noise 36..40, price 19), optimal: true ("every cheaper design was refuted in some mode").
  per_mode guaranteed Tout: normal [17.61, 37.92] ("outside ZTL", interval + corners);
  hot [34.75, 55] ("ZTL, certificate checked exactly, 477 pieces", re-checked by the independent checker).

## DOES THE ANSWER LOOK RIGHT
Checked by my own script with the TRUE Q (quadratic root), all 2^4 corners x Tamb ends: F3 hot worst Tout = 54.97 (< 55),
F2 hot 56.49 and F1 hot 58.83 (> 55), F4 only fails on noise. So EARNED F3, cheapest passing, agrees.
Hand number, F3 hot worst corner (Tamb 45, P 286, Qmax 0.04465, pmax 57.04, K 36800):
a = pmax/Qmax = 1277.5; 36800 Q^2 + 1277.5 Q - 57.04 = 0 -> Q = (-1277.5 + sqrt(1277.5^2 + 4*36800*57.04))/(2*36800)
= (-1277.5 + 3166.7)/73600 = 0.02567 m^3/s; rho = 101325/(287*318.15) = 1.1097; dT = 286/(1.1097*1007*0.02567) = 9.97;
Tout = 54.97. The tool's guaranteed upper 55 sits just above this (my g^7 bound gives 54.986). Margin is razor-thin (0.03 K).

## DOC GAPS
- Unit syntax: parentheses ("J/(kg*K)", "Pa/(m^3/s)^2") are not accepted, and the failure is a raw traceback
  (UnitError), not a BRICK ERROR. BRICKS.md should say: use only * / ^ with no parentheses, e.g. J*kg^-1*K^-1.
- Two laws defining the same derived quantity (Dp) crash with a traceback (CheckError), not a clear BRICK ERROR.
- BRICKS.md does not say whether defines may reference other defines; they can (g7 -> g6 -> ... worked) — worth stating.
- It does not say which unit names are valid for non-listed units (dBA); I used "".
- The statement "a nonlinear law that defines nothing is refused" is right, but the doc gives no recipe for the very
  common case of an operating point (curve intersection); the fixed-point bound trick above is not documented.
