# c10 report: Two-stage spur gear reducer (problem 10)

## EXPRESSED FAITHFULLY
- Torque from power and speed: `Tin = Lf*Pm/(2*pi*nm)` with Pm = 5.5 kW, nm = 1450 rpm (units checked, no complaint).
- Hertz stress with the real `sqrt`: `sigA == sqrt(S2A)`, S2A = ZE2*ZH^2*Zeps^2*K*Ft*(u+1)/(b*d1*u), K = 1.25*1.15*1.2, Ft = 2T/d1 (the 2000 in the statement is the N·m / mm conversion, SI form used), b = 12m (A) / 10m (B), stage B torque = T*uA*0.98. ZE is given as ZE2 = 189.8^2 MPa (see below).
- Ratio window 14.0..14.6, each stage ratio 2.5..5, pinion >= 17, any gear <= 110, aA within 124.5..125.5, aB within 150..175, aB >= 1.2*aA (as `gapAB == aB - 6/5*aA >= 0`) — all as stand requirements on derived quantities.
- Two load cases as `modes`: "rated" (Lf = 1, S_H >= 1.25 both stages) and "overload" (Lf = 1.1, S_H >= 1.05).
- Material slot with 3 items (slim 520/780/1450 MPa, price 2.0/3.2/5.6 USD/kg, heat-treat 0/0/4 USD/kg). S_H test written as sigma <= slim*4/5 (a bound expression with `MAT.slim`).
- Objective: `(MAT.price+MAT.ht)*Wtot`, Wtot = sum b*(d1^2+d2^2) over both stages.

## APPROXIMATED
1. **Catalog of tooth numbers pre-filtered by a script (mine, not the stand).** Per stage I generated all (m in {2,2.5,3}, z1 in 17..110, z2 in z1..110) that meet the stage's centre-distance window AND stage ratio 2.5..5 (A: 34 items, B: 533). Exact integer arithmetic, only drops infeasible rows, so safe (conservative); nobody but me checks that nothing feasible was dropped. The stand still re-checks all of these as requirements.
2. **Pairs of stages merged into one slot.** The honest two-slot brick (34 x 533 x 3 = 54k designs) was killed by the 900 s limit with NO output (not even a partial count). Final brick: one slot `G` holding (mA,z1A,z2A,mB,z1B,z2B) for each of the 778 pairs whose total ratio is in 14.0..14.6 (my script, exact fractions), x 3 materials = 2334 designs. Safe (only drops infeasible), checked only by me. The itot requirement is still in the brick, so the stand re-verifies it on the kept pairs. Cost: the stand no longer "discovers" the ratio window.
3. **Overload exemption for C45 as a hack.** "S_H >= 1.05 at 1.1x torque for 42CrMo4 and above" has no conditional-requirement syntax. I gave each material a dimensionless field `kov` (20/21 for the two steels, 1000 for C45) and required sig <= slim*kov in the overload mode. 1000 means "no real requirement". Unsafe-looking, but correct here; the stand cannot tell it is an exemption, and a reader of the JSON has to know the trick (documented in `why`).
4. **sqrt kept, but ZE^2 as a given in MPa** (36024.04 MPa) instead of 189.8 sqrt(MPa): the unit system has no half powers. Equivalent.
5. **"±10 % overload factor included separately"** read as: rated case Lf = 1 and overload case Lf = 1.1, no tolerance on P. My interpretation, not checkable.
6. **Mass ∝ b·d²** read as Σ b·(d1²+d2²) over pinion and gear of both stages. The statement is ambiguous (which d); this is my reading. Cost is "relative", so the unit (USD·m³/kg) is meaningless in absolute terms.
7. Same material for pinion and gear: S_H is the same formula for both, so one test per stage (as in the statement).
8. Hertz formula is symmetric, so I did not model the tooth-flank root stress (not asked).

## COULD NOT EXPRESS
- **The question "list all feasible (m, z1, z2) per stage and material"**: the stand stops at the first EARNED design (cheapest); with `"report":"all"` the listing is capped at 200 designs, and the first 200 are all REFUTED (the cheap materials). So the feasible set (which I computed separately: 778 designs, all 20MnCr5) cannot be read out of the stand. Only the optimum is returned.
- **Integer tooth numbers as a decision variable**: no way to say "z1, z2 integers in a range" jointly with m from a list and let the stand search; I had to enumerate rows by script (the `integers` catalog covers one field only, and constraints between fields cannot prune). 54k combinations did not finish in 900 s.
- **A requirement that applies only to some catalog items** (the 42CrMo4-and-above rule) — worked around with `kov`.
- Half-integer powers of units (sqrt(MPa)).
- Constraints between slots at the catalog level (pairing filter): not available, so the product catalog blows up.
