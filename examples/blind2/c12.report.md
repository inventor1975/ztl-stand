# c12 report: Sallen-Key 2 kHz low-pass from standard parts (problem 12)

Verdict on the brick as submitted: EARNED, cost $1.16, `optimal: true` ("every cheaper design was refuted") -- but only
over a catalog I thinned by hand to 8 resistor values x 6 capacitor values. The full catalog was not run (it cannot be).

Design the stand returned: R1 = 11.5 kOhm 1 % metal film, R2 = 35.7 kOhm 1 % metal film, C1 = 6.8 nF C0G E24 (1 %),
C2 = 2.2 nF C0G E24 (1 %), OA1 (3 MHz). Cost 0.02+0.02+0.26+0.26+0.60 = 1.16.

## EXPRESSED FAITHFULLY
- Topology and formulas: f0 = 1/(2 pi sqrt(R1 R2 C1 C2)) and Q = sqrt(R1R2C1C2)/(C2(R1+R2)) as two laws (with `sqrt`,
  `pi`).
- Four choice positions + op-amp as five slots; two resistor grades and two capacitor series as separate catalogs per
  slot; three op-amps with GBW and price; prices; objective = sum of prices.
- Tolerances: 1 % / 0.1 % resistors, 5 % / 1 % capacitors, each part independent (each part's `tolerance` is its own
  toleranced quantity).
- Tempco over 0..70 C vs 25 C: modelled as a separate catalog field `kT` per part, a range [1-d, 1+d] with
  d = ppm x 45 K (worst |dT| = 45 K). Part actual value = `R.R*R.kT` (define). This is exact, not approximate: dT is
  common but each part's tempco is free within its band, so each factor takes its whole range independently.
- Requirements: f0 within 1920..2080 Hz; Q within 0.64..0.78; sum R1+R2 <= 220 kOhm; each R >= 2 kOhm -- both on the
  ACTUAL (worst-case) resistance via derived `R1w`, `R2w` (my reading of "worst case").
- Attenuation at 20 kHz from the full second-order transfer function, no f0/Q shortcut: by hand I derived
  |H|^-2 = (1 - w^2 R1R2C1C2)^2 + w^2 C2^2 (R1+R2)^2 (H = 1/(1 + s C2(R1+R2) + s^2 R1R2C1C2)), written as law `D`, then
  `Att == 10*log10(D)`, required >= 38 dB. It is stated directly on the parts, so the f0/Q correlation is kept.
- GBW >= 150 f0 for all op-amps (law `gm == OA.GBW - 150*f0`, required >= 0).
- Capacitor values <= 220 nF: by only listing small values (see below).
- Units on everything; the stand reported `units: checked`.

## APPROXIMATED
1. **Catalog thinned to 8 R values x 6 C values (BIGGEST).** Full problem: 578 resistor items per slot x 81 capacitor
   items per slot x 3 op-amps = about 6.6e9 designs. The stand enumerates designs. A 9.0 M-design test (24 E24 resistor
   values x 2 grades, 36 cap items) did not finish in 900 s (killed by `timeout`, no output, RSS 2.1 GB at kill). A
   307 k-design test (10 R x 8 C, "generic" spacing) also hit the 900 s limit with no output. I therefore kept
   R in {11.5, 11.8, 16.5, 16.9, 34.8, 35.7, 36.5, 37.4} kOhm and C in {1.0, 1.5, 2.2, 3.3, 4.7, 6.8} nF (all E96 / E12
   values; the E24 cap catalog lists the same values, 1 %). 16 x 16 x 12 x 12 x 3 = 110 592 designs. NOT safe:
   - It is NOT conservative for "optimal": the stand's `optimal: true` is only about my 110 k designs.
   - **The values were chosen by me, with my own python model, by a greedy search to make many 1 %/E24 designs feasible and
     to keep the number of cheaper nominal-passers (which cost ~1 s each to judge) near 150.** So the catalog is tuned;
     a naive spread of values (t3: 5.11k..150k, 1.0..15 nF) had ZERO feasible designs. Checked only by me.
   - Cost depends only on grade/series/op-amp, not on values, so the cheapest PATTERN does not depend on thinning,
     provided the pattern exists in the full catalog. I checked that outside the stand (own numpy model, full E96 x E12/E24,
     all values 2k..218k / 1..220 nF): pattern (1 %,1 %, E24, E24, OA1) has 29 008 feasible value sets; the cheaper
     patterns (1%,1%,E12,E12), (E12,E24), (E24,E12) have 0; every pattern costing less than 1.16 has 0. So $1.16 is the
     true minimum of the full problem, by my model, NOT by the stand. The stand also gives a value-specific answer, not the
     value-optimal one (no value-level objective exists).
2. **E96 not supported:** `unknown series 'E96'` (BRICK ERROR). I listed items with values copied from my memory of the E96
   table (not verified against a standard). Only the chosen 8 values are used; each should be a valid E96 number.
3. **R >= 2 kOhm taken on the worst-case actual resistance** (nominal 2.00 kOhm fails), conservative. C <= 220 nF taken as
   the nominal part value (just a catalog cut) -- a looser reading; not a problem here since the chosen values are <= 6.8 nF.
4. **"GBW >= 150 f0 for OA1/OA2, >= 75 f0 for OA3 only if Q is within the limit"** is ambiguous; I applied 150 to all
   (stricter). It never binds (GBW/f0 >= 1400 for OA1, 3 MHz / 2.08 kHz).
5. **Finite-GBW effect on f0, Q and on the 20 kHz attenuation ignored**, as the problem allows when GBW > 100 f0. The
   problem also says "check with the full transfer function" -- I used the ideal-op-amp second-order function. At 20 kHz
   an OA1 (3 MHz) has loop gain only ~150; I did not model its stopband feed-through. Nobody checks this.
6. **Symmetry R1<->R2** (the model is symmetric in them) is enumerated twice; harmless, wasteful.
7. pi enters as the stand's built-in bracket (1e-15 wide). Prices used at nominal for the objective (exact anyway).

## COULD NOT EXPRESS
- A catalog at the problem's real size. No way to say "any value of the E96 series from 1.00 kOhm to 1.00 MOhm" and have
  the stand search it without enumerating 10^9 combinations: there is no pruning of a catalog by a constraint, no
  continuous/series-valued slot, no per-slot filter ("R >= 2k" is a post-hoc requirement, not a catalog cut), no
  symmetry declaration, no staging ("pick the cheapest grade pattern first, then values").
- E96 as a series (only E12/E24 are accepted).
- Finite op-amp gain A(s) = GBW/s (needs complex arithmetic / a pole in the transfer function).
- "75 f0 for OA3 only if Q is within the limit" (a conditional requirement that depends on a derived quantity).
- A requirement directly on a catalog field (R >= 2k, C <= 220 nF): requirements need a derived quantity, so I added
  `R1w`, `R2w` as identity laws for R.
- A value-level objective (e.g. "closest f0 to 2.00 kHz among the cheapest") -- only the price is minimized.

## DOES THE ANSWER LOOK RIGHT
Checked by my own python (exact fractions + mpmath at 30 digits, not the stand's code), design 11.5k/35.7k/6.8n/2.2n with
the same boxes (R: +-1 % x tempco 0.225 %; C: +-1 % x 0.135 %):
- f0 over the 16 corners: [1983.657058625, 2079.533278198] -- identical to the stand's checker (1983.65705862, 2079.5332782).
- Att: [39.3115846227, 40.1325045023] dB -- identical to the stand. Margin to 38 dB is 1.3 dB. Lowest corner used (D rises with
  every part), matches.
- Q: corners [0.74149, 0.76810]; interior scan 41 x 41 per cap corner: max 0.768099 (at a corner). The stand's Q range
  [0.7199, 0.78] is an outer range; true Q is inside it, and the requirement holds either way. The stand's reported Q lower
  end 0.7199 is not the true range, and I would not quote `guaranteed.Q` as tight (the stand says "may be wide").
- f0 high end is 2079.53 against 2080: the margin is 0.02 %. It is real (equal to my number to 11 digits), but this design
  has almost no f0 margin; the rounding of the tolerance/tempco model (symmetric tolerance x tempco) decides it. If tempco
  were taken simply as +-0.225 % added rather than multiplied, nothing changes noticeably (checked product 1.01*1.00225).
- Cheapest-pattern claim over the full catalog: my numpy scan (not the stand) over all 289 E96 resistors (2..218 kOhm) and
  E12/E24 caps (1..220 nF), with worst-case f0, Q (including the interior peak at R1 = R2), Att and sum/min R:
  (1%,1%,E24,E24) 29 008 feasible, (1%,1%,E12,E12), (E12,E24), (E24,E12), (1%,0.1%,E12,E12) 0 each. Cost ranking: nothing
  cheaper than 1.16 is feasible. This used the same model, so it checks the optimum but not the model itself.
- Not checked: that the E96 numbers I typed are the standard ones; that finite GBW does not change the 20 kHz attenuation;
  that the stand's `optimal` would hold with the full catalog (it was not run).

## DOC GAPS
- BRICKS.md says "The stand tries every combination of items across all slots" but gives no size guidance. The real
  limits found: ~100 k designs finish in 3-5 min, 300 k does not finish in 900 s, 9 M does not finish and uses 2 GB. Please state
  a limit and the memory behavior.
- Series: only E12 and E24 are documented, but the problem needs E96 (`unknown series 'E96'` appears only at run time).
- `designs_tried` counts designs tried before the first EARNED (7125 of 110 592), not the catalog size; the document does
  not say the enumeration is lazy in objective order, nor how the 99 % nominal failures cost almost nothing against ~1 s for
  each judged design.
- A catalog field with `range` inside an E-series catalog is documented; it worked in the listed form too, but the
  per-item `ground` position is unclear (I put it on the catalog, as in t19).
- No way, and no mention of the lack of a way, to put a requirement on a catalog field; the identity-law workaround is
  needed and not documented.
- The `designs` listing is capped at 200 and printed in cost order; with 99 % refuted designs most of it is noise. A flag
  to list only the earned/closest would help (not asked in BRICKS.md).
