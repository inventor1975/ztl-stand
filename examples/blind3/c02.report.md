# c02 report: insulation + window + heat pump package for a single-family house (problem 2)

Brick: `examples/blind3/c02.json` (generated by a script in my scratch folder). Verdict: **REFUTED, all 162 designs**. Run 2 min 8 s, 18 MB.

## EXPRESSED FAITHFULLY
- Three slots: insulation (18 items: EPS 6 thicknesses, mineral wool 7, PIR 5, each with its own price fixed + per mm), window (3 types), heat pump (3 sizes).
- Catalogs as stated. Lambda tolerances (+-0.003 / +-0.002) are absolute ranges on the catalog field. Window U ranges are absolute. Prices are fields.
- Wall: `Uwb == 1/Rw`, with `Rw` as a `define` holding all layers (plaster, brick, insulation x/lambda, render, Rsi, Rse). Brick lambda is a given range 0.57..0.67. Each layer thickness and lambda is a given with a unit (mm, W/(m*K)), so the "bare number is SI" pitfall does not apply.
- H_T = (Uwb + 0.05)*142 + Uwin*26 + Uroof*90 + b*Ufloor*90. Roof and floor U are given ranges, b = 0.6. H_V = n*V*0.34 Wh/(m3 K), n a range 0.3..0.7 1/h. Umean = H_T/348.
- Heat pump: Pmargin = Pnom*(1 + 0.015*(Tout + 7)) - Htot*(20 - Tout), Tout a range -14..-10 C, required >= 0. The correlation of T between capacity and loss is kept (one quantity).
- Energy: Eht = Htot*DD, Enet = Eht - Gains, DD range 3000..3600 K*day, gains 2500..3500 kWh, required <= 9000 kWh. The "24/1000" factor comes out of the unit system (W/K * K*day -> kWh), I wrote no conversion constant.
- Requirements: Uwb <= 0.22, Umean <= 0.35, Pmargin >= 0, Enet <= 9000, all over the whole box (for all).
- Objective: minimize 20-year cost = insulation (p0 + p1*x)*142 + window price*26 + HP price + 20*nominal electricity (Enet_nom/COP*0.28). Done with `computed` and a nominal objective.
- Units checked ("every law's dimensions agree"), including kWh, 1/h, K*day, EUR/(m^2*mm).

## APPROXIMATED
1. **Nominal copies for the cost (not conservative or not, it is cost only; checked by nobody).** `computed` and the objective may not read toleranced quantities, so I added exact twins: `lbr_n` 0.62, `Urn` 0.14, `Ufn` 0.30, `nac_n` 0.5, `DD_n` 3300, `Gain_n` 3000, `COP_n` 3.2, catalog `lam_n` (0.036 ...) and window `U_n`. Nobody checks that a twin equals the midpoint of its toleranced partner; I typed both. A mismatch would only shift the cost ordering, not any verdict. Also the wall formula is written a second time in `computed` (`Uwn`) as well as in the law.
2. **COP +-0.3 is not in the brick.** COP appears only in the 20-year cost at nominal values, so only 3.2 is used. No requirement depends on it. Safe for the verdicts.
3. **Lambda tolerance as ranges, and Uroof/Ufloor "fixed +-" read as plain tolerances** (0.13..0.15, 0.27..0.33). That is how the problem reads; the roof "fixed" wording is ambiguous in the problem itself.
4. **Heat pump formula validity (T <= -7) is not stated as a law domain** (`valid`). The range -14..-10 is inside it, so harmless here, but the brick would silently extrapolate if the range were changed.
5. **Insulation thickness and area quantities are exact** (as in the problem). The wall area for the price (142) is the same given as in the heat loss.
6. Nothing was hand-algebra'd, no bound computed outside; the worst case is the stand's own (T range, not a hand-picked T = -14).

## COULD NOT EXPRESS
- A **nominal** value of a toleranced quantity (for the cost) has no accessor; I needed duplicates (APPROXIMATED 1). A midpoint reference would remove the duplication risk.
- Nothing in the physics was inexpressible. The cost objective with a nominal value of a derived quantity (the energy) had to be recomputed by hand in `computed` instead of reading `Enet` (the objective cannot name derived quantities unless `case: worst`, which is the wrong meaning here: the problem wants nominal).
- The 20-year cost itself is not "judged" by anything: it is a plain evaluation, no check of its units beyond what `computed` does.

## DOES THE ANSWER LOOK RIGHT
I wrote an independent python float model (all 162 designs, all unfavourable extremes together: lambdas high, brick lambda 0.67, U's high, n 0.7, T -14, DD 3600, gains 2500).
- Worst-case net energy: minimum over all designs is 9189 kWh (PIR 140 mm + W3K + HP6), above 9000. So nothing passes; REFUTED matches, and the stand's "energy requirement alone is the conflict" matches. Without the energy requirement 52 designs pass the other three in my model.
- Stand's guaranteed upper bounds on the relaxed run equal mine: Enet 10742, Uwb 0.1753, Umean 0.2865, Pmargin low 0.159 kW. Cost 29719.99 EUR equals mine to the cent; cheapest-first order and "optimal" agree (EPS200/W2/HP6 is the first in my cost ordering and passes at 11000).
- Hand check of the closest design's witness: R = 0.13 + 0.015/0.70 + 0.25/0.62 + 0.14/0.036 + 0.01/0.87 + 0.04 = 4.4950, U = 0.22247. Matches `value_there`.
- Not checked: the individual witness `by` values of the other 161 designs (the stand's witness is the nominal point or one corner, e.g. EPS 200 W2 HP6 gives 537 kWh over; my worst-case figure is 1742 kWh over, so `by` understates the worst violation, as the doc says). The objective of designs that were refuted. The data itself (my reading of "b applies to the floor in H_T" is mine).
- Honest note: the answer "nothing passes" is a real property of the invented data (best worst-case 9189 > 9000), not a brick error, but it makes the example weak on the EARNED path; I tested that only through the relaxed side run.

## DOC GAPS
- BRICKS.md does not say `computed`/objective cannot read toleranced quantities in a way that hits people: the sentence is there ("without tolerance") but there is no recipe for "nominal cost of a toleranced design", which every cost objective with tolerances needs.
- The doc does not say what `closest_design` means for REFUTED when each design has a different failing requirement: it is chosen by the witness-point overshoot, not by the worst case. It misled me at first (it points at a design that is not nearest to passing).
- `report: all` lists only the FIRST failing requirement per design, so "which requirements does each design fail" cannot be read from one run (the doc says "the requirement it fails").
- Run time is not stated: 162 designs with 9 toleranced quantities took 2 min; 90 were dropped at nominal in under a second. A note on cost per judged design would help.
- The line "ZTL left it unbounded (a product of toleranced quantities)" appears for Uwb (a pure 1/(sum) of toleranced values) and for Pmargin; the doc says only "products". Division and sums of toleranced values in a denominator are also outside ZTL today.
