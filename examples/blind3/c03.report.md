# c03 report: bladder accumulator for an emergency stroke (problem 3)

Brick: `examples/blind3/c03.json`. Verdict: **EARNED**, cheapest = A32 (32 L, 740 EUR) with pre-charge 80 bar. A50 and A80 at 80 bar also pass. No other pre-charge step passes for any size. A10 and A20 pass for none.

## EXPRESSED FAITHFULLY
- Gas law as stated, no hand algebra except one rewrite (see APPROXIMATED, item 1): `dVf == V0*(pow(p0T/p1a,5/7) - pow(p0T/p2a,5/7))` with n = 1.4, so 1/n = 5/7. The `pow` exponent `5/7` was accepted as a constant.
- Absolute pressures: `p1a = p1 + patm`, `p2a = p2 + patm`, patm = 1.013 bar.
- p1 = 105 ... 115 bar (range), p2 = 210 bar exact.
- T = 263.15 ... 333.15 K (range). Pre-charge at temperature: `p0T = (p0_20 + patm)*T/Tref`, Tref = 293.15 K.
- Pre-charge slot: 13 listed items, 60 ... 120 bar in 5 bar steps. Accumulator slot: 5 listed items (V0, price).
- "Design for the larger dV_req": a given `dVreq = 6.5 L, tolerance 3/65` (exactly 6.2 ... 6.8), used as the bound of `dVf >= dVreq`. The proof uses its least favourable end, 6.8.
- Bladder rule 0.6 p1 <= p0(T) <= 0.9 p1 (gauge): derived `rpre == (p0T - patm)/p1`, `within [0.6, 0.9]`. The temperature and p1 correlation stays exact because it is one quantity.
- Compression ratio `cr == p2a/p0T <= 4`.
- Vessel limit: `vmargin == Pvessel - p2 >= 0`. This is trivially true (40 bar). It is included only so the 250 bar rule is in the brick.
- Slow case (n = 1, 20 C): `dVs == V0*(p0a20/p1a - p0a20/p2a) >= 2.0 L`, with p1 over its range.
- Objective: minimize ACC.price, `report: all`.
- Units: "checked: every law's dimensions agree" (bar/bar ratios under `pow` were accepted as dimensionless).

## APPROXIMATED
1. **Algebra rewrite (safe, checked by the stand's unit and number machinery; the rewrite itself is checked only by me).** `p0^(1/n)(p1^(-1/n) - p2^(-1/n))` became `(p0/p1)^(1/n) - (p0/p2)^(1/n)`, because `pow` with a non-integer exponent needs a dimensionless base. It is the same number. I checked it numerically in Python, not formally.
2. **Interpretation, not conservative either way: how the pre-charge scales with T.** I scale the ABSOLUTE pre-charge (set gauge + 1.013 bar) by T/293.15 and subtract 1.013 bar for the gauge rule. The statement says only "p0(T) = p0(20 C) * T/293.15" and "use gauge pressures for this rule", which can also be read as scaling the gauge value. I ran that variant in scratch (`var_gauge.json`). The result is identical (same 3 designs, rpre range 0.6245 ... 0.8659 instead of 0.6236 ... 0.8672), so the answer does not depend on the reading. Only I check this.
3. **Slow case p1 range:** I used the same p1 = 105 ... 115 bar and the same pre-charge (set at 20 C, no temperature range). The statement says "between p1 and p2 at 20 C" and does not say which p1. Reading p1 = 100 ... 120 would be harsher; I did not run it.
4. **Time windows (4 s, 5 min) are not modeled.** They only choose n = 1.4 or n = 1.0, which I hard-coded as two separate laws (dVf, dVs).
5. **Reported `guaranteed` range for dVf is [6.8, 13.98].** The lower end is the threshold the certificate proved, not the true minimum (true min = 7.97 L, Python grid; the stand's value is a sound lower bound only). The upper end 13.98 is an outer range (true max about 11.24). Not an error, but it reads like a computed range and is not.

## COULD NOT EXPRESS
1. **Selecting the regime by time.** "4 s means adiabatic, > 3 min means isothermal" cannot be stated as a rule. I wrote the two cases as two named quantities, so the link between time and n lives only in my head and in the `source` text.
2. **Pre-charge step as a rule ("steps of 5 bar from 60 to 120").** Only listed items work for this (the integers catalog has step 1). I listed 13 items by hand. `computed` could have done `5*k` but needs an integer catalog, and I did not need it.
3. **"Cheapest" when many designs tie.** Price depends on size only, so the 3 passing pre-charge steps give no tie-break (only one step, 80 bar, passes, so no real issue here).
4. **Per-case p1 or temperature ranges** (fast case: T over the full range; slow case: T = 20 C; bladder rule: p1 = 105 ... 115) all share the same global given quantities. This happened to cost nothing because dVs does not read T. A brick where two requirements need different ranges of the same quantity would need `modes`.
5. Nothing here needed `if`/branching. The statement's "gauge or absolute" ambiguity cannot be expressed as an alternative either (I ran a second brick for it).

## DOC GAPS
- BRICKS.md says nothing on how a requirement bound given quantity with a tolerance (`dVreq` with `tolerance`, used only as a bound) is treated. It worked (least favourable end = 6.8 for `>=`), but I had to guess; it is mentioned only for `slot.field` and for expressions. It would help to say that the witness point can use any value of that quantity (6.2 here), so `by` is not against the worst end.
- `pow(x, 5/7)`: "any other exponent needs a dimensionless x" does not say a fraction `5/7` is a legal constant exponent. It is.
- `guaranteed` for a certificate-checked quantity can show the requirement threshold as its lower end; this is not said. Easy to misread as the computed minimum.
- "A temperature unit C is a difference with no offset" is clear, but nothing says that an absolute range in K must be written as K numbers (263.15 ...), which is what I did.
