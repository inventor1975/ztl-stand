# c05 report: Drive for a loaded belt conveyor, induction motor + gearbox (problem 5)

Final brick: examples/blind3/c05.json (3 modes, 3 slots M / RAT / GB, 36 designs, implicit law for the operating point).
Verdict: EARNED, cheapest = M18 + ratio 25 + G3, 2800 EUR, `optimal: true`. Also EARNED: M22+25+G3 (3050), M30+25+G3 (3600). 33 of 36 REFUTED.

## EXPRESSED FAITHFULLY
- F = 9.5 kN +-10% (tolerance), D = 0.5 m, V = 360..420 V (range), motor torque scale (V/V0)^2, T_L = F*D/2, breakaway 3/2 * T_L.
- Motors (Tn, ns=1500 rpm, price), ratios {20, 22.4, 25, 28} with eta 0.96 / 0.95 for 28, gearbox sizes (Tr, price) as three catalogs / three slots, so "triples" = 3x4x3 = 36 designs.
- Operating point as an IMPLICIT law: `M.Tn*Kop*Vs2 == F*D/2/(i*eta)`, root searched on xop in [0.88, 1] (the falling part). Kop is the torque-curve multiple written with nested `if` (8 linear pieces, exact fractions: 21/10 - 3/2 x, ..., 1 - 200/3 (x - 197/200)). Unique root is checked by the tool, not by me.
- (a) belt speed: v = pi*D*ns*xop/i, vrel = v/1.6, required vrel within [0.96, 1.02].
- (b) as modes. "breakaway": x in [0, 1/20], kb = 3/2. "sweep": x in [1/20, 22/25], kb = 1. Quantity xs is a GIVEN with a range, i.e. the stand's "for all" is used as "for every speed in the range". mb = Tn*K(xs)*Vs2 - kb*F*D/2/(i*eta) - Tn/4, required >= 0 (V takes its full box, so the lowest voltage is the binding one).
- (c) Tsh = TL/(i*eta) <= M.Tn. (d) TL <= GB.Tr*5/7 (1.4 service factor) and Tbk <= GB.Tr.
- Objective: minimize M.price + GB.price (ratio has no price in the problem).

## APPROXIMATED
- Torque curve: the table was converted by me into 8 slope/intercept pieces (hand algebra, exact fractions). Safe in principle, but NOT checked by the stand: a transcription error would be invisible to it. I checked the pieces numerically with numpy interpolation of the original table (see below).
- Breakaway region x < 0.05 is closed to [0, 0.05]; the sweep region starts at 0.05 with kb = 1. At x = 0.05 both factors are applied in different modes, so the point 0.05 is tested with 1.5x as well (stricter than "x < 0.05"). Since the motor curve is continuous the infimum over x<0.05 equals the value at 0.05, so the verdict is not changed. Conservative / equivalent.
- (b) is not applied on (0.88, 1.0) as the problem says (0 ... 0.88 n_sync only) - I follow the problem. Sweep range upper end 22/25 = 0.88.
- (c) is ambiguous in the problem ("motor shaft torque at the operating point <= 1.0*T_n at the lowest voltage"). At equilibrium the shaft torque equals the load torque at the motor shaft whatever the voltage, so I required Tsh = F*D/2/(i*eta) <= Tn over the whole F box. I did NOT scale Tn by (Vmin/400)^2. If the intended reading scales Tn, this is a different (stricter) requirement; this is my reading, nobody checks it. Under the scaled reading the answer WOULD change: M18 i=25 has Tsh max 108.9 vs scaled Tn 97.2 and would fail, M22 passes narrowly (scaled Tn 115.0 vs 108.9), so the cheapest would become M22 + 25 + G3 (3050 EUR). I did not run this variant. Worth asking the problem author.
- Rated speeds (1470/1475 rpm) and rated powers of motors are not used: the curve is given as "identical in shape" with rated point at 0.985, not at 1470/1500 = 0.98. Not modelled; no effect on the stated requirements.
- Speed requirement expressed as vrel in [0.96, 1.02] (trivial hand conversion of -4%..+2%).
- Hand-splitting was NOT needed in the end: I first split the sweep into 5 segments (71 s run), then found a single sweep over [0.05, 0.88] gets a 3-piece certificate (26 s). Both give identical verdicts.

## COULD NOT EXPRESS
- A tabulated curve with linear interpolation (no table primitive; I wrote nested `if`s by hand).
- "For all speeds in a range" as a requirement over a function of a free variable: only through a given with a range (works, but it is a trick; the sweep variable also exists in the "operating" mode where it is unused, and xop exists in the sweep modes).
- Requirements local to a mode while top-level requirements apply to all modes: forced me to put every requirement in a mode (top-level `requirements` is an empty list). Laws cannot be scoped to a mode with a given override only; unused laws are still computed in every mode (cost).
- Statement (b) as "strictly x<0.05" vs ">= 0.05" (no half-open ranges).
- The "operating point is on the falling part of the curve" selection is by `search` range only; the stand does not know why. If there were another intersection with x >= 0.88 it would pick all roots (here the curve is strictly falling there).
- The consistency between the table and the rated data (0.98 vs 0.985) is not checkable.

## TOOL OUTPUT
- Variant A, one mode, kb=1 only (no breakaway): 2.4 s, EARNED M18/25/G3 - but this variant omits the breakaway case, I did not use it as final.
- Variant B, 7 modes (breakaway + 5 hand segments + operating): 71 s, EARNED, same result.
- Final, 3 modes: 26 s, 1 core, 3 GB cap, no kill. `designs_tried 36`, `REFUTED 33`, `EARNED 3`, objective 2800, `optimal: true` ("every cheaper design was refuted in some mode").
- `how`: vrel "ZTL, interval reading of the definition (sound, may be wide)" with the checker's own bound equal; Tsh/TL/Tbk "exact at the corners"; breakaway mb "interval reading" [2839/800, 91389/800]; sweep mb "certificate checked exactly (3 pieces) ... checker re-checked the same certificate".
- The implicit law with a nested `if` of depth 7 in a define worked at first try. No errors, no crashes, no STAND FAULT.
- Per-mode refusal reasons: 22.4 and 28 fail (a) (speed too high / too low), 20 fails (a) (and (b) breakaway for M18), G1/G2 fail (d).

## DOES THE ANSWER LOOK RIGHT
My own numpy check (chk.py in my scratch folder: interpolates the original table, finds the root on [0.88, 1] at the 9 corners of (F, V) and also F nominal, a dense x grid for (b), hand formulas for (c)/(d)): exactly 3 designs pass (M18/25/G3, M22/25/G3, M30/25/G3), the same as the stand.
- M18, i=25, G3: vrel range by numpy 0.9617..0.9718; stand 0.961725..0.971834. Match.
- Breakaway margin M18/25 by hand: 120*2.025*0.81 - 1.5*108.854 - 30 = 3.549; stand lower end 3.54875. Match.
- Sweep margin true minimum by hand: 120*1.8*0.81 - 108.854 - 30 = 36.1 (at x = 0.2); stand's "guaranteed" prints lower end 0, i.e. the requirement bound, not the true minimum (certificate only proves >= 0). Not a wrong claim, but not the tight range.
- G3 forced: 1.5*2612.5 = 3918.75 > 3300 (G2) and 1.4*2612.5 = 3657.5. Match.
- Not checked: the exactness of the 3-piece certificate itself (I trusted the tool's checker); ratio 25's distance to the lower speed limit is 0.2% of v (0.9617 vs 0.96), which is tight, so the result depends on the single digit in eta = 0.96 and the curve point (0.985, 1.0).
