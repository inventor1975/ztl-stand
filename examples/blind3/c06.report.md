# c06 report: Mix for C30/37 slab concrete (problem 6)

Verdict: EARNED, optimal true. Design: CEM II/A-L 42.5N + superplasticiser, w/c 0.48, slump class 60-180, blend 45/20/35 (sand / 4-16 / 16-32), cost 92.8663 EUR/m^3 (nominal air). Brick: `examples/blind3/c06.json` (generated by a python script from my scratch folder; 31 w/c values x 231 blends x 2 x 2 x 3).

## EXPRESSED FAITHFULLY
- Strength: table in w/c with linear interpolation, written with nested `if(...)` over four table points given as quantities (F40..F55, W40..W55); CEM II subtracts 3 MPa (catalog field `dC`); table scatter +-2 MPa as one given range `etab`; plant sigma `s` in [3,5] MPa as a given range. Requirement `fm >= fck + 1.48*s`, so the stand takes the worst s itself (I did not substitute s = 5).
- Cement content `Cdel` within 300..400 kg/m^3 (a requirement, so it is judged, not assumed).
- Volume balance as a law: `Mag == RHOA*(1 - C/RHOC - W/RHOW - air)` with air a given range 1..3 %.
- Sand moisture 4% +-2% (given with tolerance 0.5 -> 2..6 %), `Wsand == mois*xs*Mag`, `Wfree == W - Wsand`, required `>= 0`.
- Plasticiser: catalog (none / yes: reduction 12%, dose 1% of cement, 1.4 EUR/kg), water reduction in `W = Dem*(1 - red)`.
- Slump class: a 3-row catalog (30-60: 190, 60-180: 205, >180: 220) with a `where` that keeps only classes that contain the whole delivered range 100..150 mm (given Smin, Smax). Result: only the 205 class survives.
- Grading: each fraction's passing at 5 sieves as given quantities; combined passing computed per blend; 5 envelope requirements; sieving error +-3 points as a given range per sieve.
- Prices in EUR/t and EUR/kg with units; overhead 18 EUR/m^3; objective = cost per m^3. Cement type, plasticiser yes/no, blend (5% steps, sum 100%) are slots.

## APPROXIMATED
1. **w/c "any value 0.40..0.55" became a grid of 0.005** (31 values). Not conservative in general: a continuous optimum between grid points would be missed. Checked by me, not the stand: I reran with step 0.001 (151 values, with the pre-filter below): same winner, same cost. It is also the analytic optimum (strength is tight at 37.4 MPa at 0.48 for CEM II).
2. **Cost uses nominal air (2%)** through a separate exact given `airn`, because a nominal objective cannot read a derived quantity or a ranged one. The true cost moves by about +-0.3 EUR/m^3 with air 1..3%. The "cheapest" claim is therefore for nominal air; the stand does not check the worst-case cost (I did not use `case: worst`, which would judge all 6768 designs).
3. **Sieving error is one error per sieve on the combined passing** (not per fraction), clipped to [0,1] by `min(1, max(0, S+e))`. Worst case is the same as with per-fraction errors (weights sum to 1), but the clipping at 0 and 100% is my physical reading, and without it every design failed the 32 mm sieve (98..100 + 3 > 100). Only I checked this reading. Unclipped reading would be REFUTED for everything.
4. **Table scatter is one common +-2 MPa** for the interpolated value, not independent per table point. Same worst case; safe for the range, but not the same random model.
5. **The table beyond w/c 0.55 (0.60, 0.65) is dropped**: the grid ends at 0.55 by the durability limit, so those rows are never read.
6. **Water density: 1 L = 1 kg**, so water is in kg/m^3 (units: L/m^3 would make W/1000 dimension-wrong). Plasticiser mass/volume is not entered in the volume balance (the problem does not give its density). Aggregate mass in the balance is taken dry; moisture is "by mass of sand".
7. **Total water W (including sand water) = cement*(w/c)**, my reading of "the water in the sand counts toward the mix water". Consequence: sand moisture does not influence strength or cement; it only affects `Wfree >= 0`, which is true for every design (a weak requirement I added myself).
8. The slump lookup is done by catalog + `where` (exact, not judged by ZTL). The stand just filters; I wrote the class limits. I checked by eye that only the 60-180 class contains 100..150.
9. Pre-filter in the 0.001 verification run (`where` with nominal grading and cement limits, both necessary conditions) is in my scratch folder only, not in c06.json.

## COULD NOT EXPRESS
- A continuous design choice (w/c in [0.40, 0.55]). Only a discrete catalog; a finer grid costs run time linearly.
- A worst-case objective together with `where`-pruning at no cost; the worst-case cost over air is not in the nominal objective.
- Physical clipping of a percentage to [0,100] has to be written by hand with min/max (it worked, but it is a modelling step the stand does not know about).
- Tolerance on a catalog item's price/composition as a joint "random" set; not needed here.
- Nothing needed to be given up otherwise. Table points of the strength curve are 8 given quantities, not a table object.

## DOC GAPS

- Not stated whether `min`/`max` with a bare `1` or `0` against a dimensionless quantity is fine (it is).
