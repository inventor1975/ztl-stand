# c07 report: Photo-survey quadcopter, drone endurance (problem 7)

Verdict: EARNED, optimal. Design: propeller P2 17x6, battery B1 LiPo 8000 mAh, 2 packs, 505 EUR. 12 designs tried, 1 earned, 11 refuted, 0 open. Run time 1.2 s wall (limit 900 s, 3G); no kill.

## EXPRESSED FAITHFULLY
- Three slots: propeller (2 items), battery type (3 items), pack count (integers 1..2). 12 designs = the 12 combinations asked about.
- Propeller rows (D, c_T, FM, max rpm, price) and battery rows (Ah, mass, C-rating, price), all with the stated units.
- m = 2.3 kg + packs + payload; W = m g with g = 9.81 (own given quantity, not the built-in g0 = 9.80665).
- Induced power per rotor T^1.5/sqrt(2 rho A) with T = m g/4 and A = pi D^2/4; divided by FM and eta; times 4; plus 18 W.
- Hover time = n_packs * Ah * 22.2 V * f_usable * k_cold / P_el, in min.
- Hover rpm from T = c_T rho n^2 D^4, requirement n <= 0.65 * rpmmax.
- Peak current from 1.6x-weight thrust, power scaled with T^1.5, divided by 22.2 V, bounded by C-rating * n_packs * Ah.
- Take-off mass <= 7.0 kg; objective = cheapest total price.
- "For all" over rho in [1.05, 1.225], eta, f_usable, c_T, FM, and payload in [0, 1.5]. The two endurance cases and the "all payloads" case are three modes.
- Cost = n_packs * pack price + propeller set price.

## APPROXIMATED
- Tolerances written as absolute ranges (eta [0.75, 0.85], f_usable [0.77, 0.83], c_T +-0.008, FM +-0.04) instead of relative tolerances. This is exact, not an approximation. The stand checks them.
- Condition (a) is stated at two fixed payload/temperature points, so it is two modes with fixed payload and kT (1 and 0.85). The "all payloads" mode holds (b), (c), (d). Condition (a) is not checked over the whole payload range, which the problem did not ask. (b), (c), (d) are checked in the all-payloads mode only. They are not checked in the two endurance modes; these are weaker cases, so nothing is lost. Only I checked this reading.
- Peak current: I scaled only the propulsion power by 1.6^1.5 and added the 18 W avionics unscaled. The text ("electric power at that thrust, scaled with T^1.5") could mean scaling everything. Scaling everything adds 18 W * (1.6^1.5 - 1) / 22.2 V = 0.83 A. The verdicts do not change: the winner has 74 A against a 400 A limit. Only I checked this.
- Peak-current limit uses nameplate capacity, not the 0.85 cold-derated one. The problem text says "total capacity". Not conservative if the cold derating was meant. For the winner it makes no difference (74 A against 340 A).
- Cold only affects capacity (x0.85), not rho or the motors. This follows the problem. rho covers the full range in every mode, so the density worst case is held anyway.
- The rpm bound is evaluated with the hover mass that includes payload [0, 1.5] and all rho; the problem says "at the lowest density". The stand takes the worst over the whole rho range, which includes the lowest, and it is the same or stricter. Safe.
- `pi` is the stand's 1e-15-wide rational bracket (negligible).
- Pack count is handled as a multiplier of mass/Ah/price in laws. Nothing is hand-algebra except writing T^1.5 as sqrt(T^3/(2 rho A)) so that each toleranced variable appears once in the expression (so interval arithmetic is not widened by repeats). That is algebraically identical. Checked by my own python (see below).

## COULD NOT EXPRESS
- Nothing essential. Two small things:
  - A rule "3C max discharge" is only a C-rating field; there is no way to say whether it is peak or continuous (the problem does not say either).
  - There is no way to state that rho, eta, etc. must be the SAME draw between the two endurance modes. Not needed here: each mode is a separate "for all", which is what the problem says.
- No `valid` domain was needed.

## DOC GAPS
- BRICKS.md does not say whether a definition may divide by another derived quantity (`tfl == E/Pel`). It works, and the stand labels it "outside ZTL" for that line. The statement in section 4 about the linear class does not describe this case.
- A mode's `quantities` override with only `value` for a quantity that had `range` at the top level works (I used it) but is not shown; the example has `value` with `tolerance`.
- It is not said that an integers catalog can be a slot with its own field name (here `NB.N`); I took it from the catalog description and it worked.
- Fractional dimension inside sqrt (kg^2 m^4 s^-6 under the root) works, but the doc only says "transcendental needs dimensionless" and does not say that sqrt of a dimensioned expression is fine.
- Not said how `rpm` as a unit converts (I got 1/60 Hz as expected from the results, matches my python).
- `pow(x, 3)` on a toleranced given works; the doc says integer exponent carries the unit, ok.
