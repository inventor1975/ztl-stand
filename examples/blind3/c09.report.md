# c09 report: Tank size for a house rainwater system (problem 9)

Brick: `examples/blind3/c09.json` (generated by a script in my scratch folder; the JSON itself is plain, ~150 laws).
Verdict of the brick as stated: **REFUTED** (all 10 tank x filter pairs). No cheapest pair exists because no pair passes.

## EXPRESSED FAITHFULLY
- Roof area 180 m^2 +-5% (`tolerance`), runoff coefficient range 0.70..0.90, household demand 140 L/day +-15%.
- Filter efficiency as a catalog `range` field per filter set (basic 0.85..0.90, premium 0.90..0.95), price 650 / 1100.
- Tanks 3 / 5 / 7.5 / 10 / 15 m^3 with prices; installation 380 EUR/m^3 as a given with unit EUR/m^3; objective
  `T.price + inst*T.C + F.price`.
- All 12 rain values and 12 day counts as givens with units (mm, day); garden 120 L/day only in months 4..9 (in the
  `define` of D4..D9).
- The month recursion exactly as written: `S_k == min(C, max(0, S_{k-1}+Y_k-D_k))`, `U_k == max(0, D_k-S_{k-1}-Y_k)`,
  `O_k == max(0, S_{k-1}+Y_k-D_k-C)`, S0 = 0.5*C. Whole-year sums Utot, Otot.
- Three years as three `modes` that override one given `fy` (0.75 / 1 / 1.15), the same 48 laws in every mode.
- "Months with shortage" as `sh_k == if(U_k > 0, 1, 0)`, `Nshort == sum sh_k`; requirements Nshort <= 3 (dry), <= 1 (normal).
- Worst case over area, runoff, demand, filter efficiency: this is simply the "for all" over the box. No hand-picked corners.
- Units checked (no "not checked" line); L = m^2*mm and L/day*day close correctly.

## APPROXIMATED
- **Percent requirements turned into margin quantities** (hand algebra, exact, safe): `Mu == Utot - 0.12*Dtot` required
  `<= 0`; `Mo == Otot - 0.25*Ytot` required `<= 0`. Equivalent to the ratio form (Dtot, Ytot > 0). The stand checks
  the arithmetic; I chose the form (a ratio would lose correlation, BRICKS.md section 6).
- **Uncertainty applied to all three years.** The text names the worst-case set only for the dry year; I applied the
  same box (area, runoff, demand, filter efficiency) to the normal and wet years. This is the conservative reading; only
  I decided it. (If the normal year were meant at nominal values, the outcome could change.)
- **Overflow definition.** The text says "overflow = yield above C"; I read it as `max(0, S+yield-demand-C)`
  (what the min() in the S-recursion cuts off). My reading, nobody checks it.
- **Wet-year yield for the 25% test** is the sum of Y_k of that year (before the tank), not the sum of water entering the
  tank. Same reading, mine only.
- Single year from 1 January at 50% full, as stated (not a periodic steady state). Nothing changed.
- `report: "all"` added so all 10 pairs are listed.

Nothing else was dropped: no bound computed outside, no rounding.

## COULD NOT EXPRESS
- Nothing essential. Awkward points:
  - An indicator count is written with 12 `if(U>0,1,0)` quantities plus a sum; no counting construct.
  - The year factor is an override of a given in a mode, so "dry/normal/wet" is expressible only as modes; there is no
    way to ask for a single combined statement over the three years (not needed here).
  - The S-recursion is 12 laws x 4 quantities; there is no loop/array. 48 laws + 14 derived + 24 defines written by a script.
  - A REFUTED result under modes shows only the first failing mode per design (see below); I could not ask "all failing
    requirements" (no minimal_conflicts across modes per BRICKS.md).

## TOOL OUTPUT
- Faithful brick (`c09.json`): REFUTED, 10 of 10 designs; `designs_tried 10`, `undecided 0`; run time 0.66 s
  (real). Closest design: 15 m^3 + basic filter, `failing_mode: normal year`, `Nshort` = 3 at the witness
  (A=180, rc=0.8, hh=140, eff=7/8), overshoot 2. Every design is listed as failing in "normal year".
- Per-mode single-mode runs of the same brick (scratch): dry year alone REFUTED (all 10), normal alone REFUTED (all 10),
  wet alone REFUTED (all 10). So all three year-requirements fail independently.
- **STAND ERROR, in relaxed variants of my brick (scratch only, not in c09.json).** I relaxed the thresholds to see the
  EARNED path (dry-year unmet <= 45% / 55% / 60% of demand; the 90% and 70% variants ran fine and gave EARNED for all):
  `STAND ERROR ... NoDerivative: max has no derivative where its arguments cross (at zcertify.py:106)`.
  It occurs whenever the interval reading of `Mu` (unmet margin, a sum of max() chains and the demand total that
  depends on the same `hh`) is too loose to decide and the stand falls back to the certificate search; it appears even
  when the true answer is clearly EARNED (c55: sim max unmet 0.506 <= 0.55). Count and overflow-per-box requirements in the
  relaxed runs went through fine (normal-year counts <= 4: EARNED for 10 m^3 premium and 15 m^3 both; dry counts <= 6:
  EARNED for 7.5 premium, 10, 15; dry counts <= 9: EARNED for all).
  Consequence: with the real numbers, an unmet-fraction requirement that was passable but close would crash instead of
  give a verdict. In the faithful brick it did not trigger because the witness search refutes first.

## DOES THE ANSWER LOOK RIGHT
I wrote an independent python simulation of the 12-month recursion and took the 16 corners of (A, rc, hh, eff) per
filter set (everything is monotone in these, so the worst case sits at a corner; this monotonicity I argued, not proved).
- Worst case number of short months, normal year: 3 m^3: 6, 5 m^3: 5, 7.5: 5, 10: 5 (basic) / 4 (premium), 15: 4. Requirement <= 1.
  Dry year: 6..7 months everywhere (requirement <= 3). Both fail for every pair, consistent with REFUTED.
- Worst dry unmet fraction: 0.41 (15 m^3 premium) .. 0.51 against the 12% bound; worst wet overflow fraction 0.265 .. 0.52
  against 25% (even 15 m^3 premium: 0.346; 15 m^3 basic: 0.318). All fail. Reason: annual demand is ~73 m^3 against a yield of
  ~70 m^3 at nominal (less in a dry year), so no tank of the given sizes can reach the targets.
- Stand's witness numbers: the dry-year witness for 3 m^3 basic, `by` = 24378.3 L, equals my simulation exactly at the nominal point
  (A=180, rc=0.8, hh=140, eff=0.875), U - 0.12*D = 24378.3. Nshort = 3 for 15 m^3 at the nominal point matches my sim.
- Relaxed variants vs sim: normal count <= 4 EARNED exactly for (10 premium, 15, 15); dry count <= 6 exactly for (7.5 premium, 10, 15);
  these match the corner table above (the worst counts 4 and 6).
- Not checked: the stand's `guaranteed` ranges for EARNED variants; why the witness is at nominal, not the worst corner
  (it is "a" violating point, so the `by` is not the worst overshoot).

## DOC GAPS
- Nothing in BRICKS.md says that min/max with a crossing derivative can crash the certificate search (NoDerivative); the doc
  says only that certificates are searched when the interval is too wide.
- A REFUTED verdict under modes reports one failing mode per design (here the normal year, not the dry year, though dry
  also fails, and the order of modes is not stated). The doc does not say which mode is shown.
- `if(U > 0, 1, 0)` with a bare 0 against a derived quantity worked, but the doc does not say bare numbers are allowed
  in a comparison against a quantity with a unit.
- It is not documented that `if` indicators sum correctly (hull [0,1] per undecided month) nor how tight the count bound is.
- `witness` description "by" is in the quantity's own unit (here L for the margin) -- fine, but for a margin quantity this is
  not the fraction the requirement talks about, so one must recompute.
