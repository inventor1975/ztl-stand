# c01 report: Passive vaccine shipper, insulation panel + PCM mass (problem 1)

Final brick: `examples/blind4/c01.json` (generated by `work_c01/gen.py`, step 0.01 kg, N 0..1600, "faithful" form).

## EXPRESSED FAITHFULLY
- All 12 insulation options as a listed catalog (t, k_eff as range nominal +/- absolute tolerance, price, density; name as label). Slot `INS`.
- Geometry as `define`s from given outer edges: Vin, Aout, Ain, Am = sqrt(Aout*Ain), UA = k*Am/t (k toleranced, so UA is toleranced).
- Uncertain data: L in [185,215] kJ/kg, Cp in [30,34] kJ/K, k in nominal +/- tol; f_s in [0.85,1], f_c in [0.70,1] (independent, per lane).
- Two lanes as two `modes` that override Ta, f and a sign `sg` (+1 hot, -1 cold). One shared law set, so the same box and same m in both lanes.
- Phase 1/2 physics as written, with the exact functions: `t1 == f*m*Llat/(UA*dT)`, `tau == (Cp+m*cpcm)/UA`, `Tend == Tm + sg*dT*(1 - exp(-max(0, tend - t1)/tau))`. The `max(0, ...)` makes T = 5 C when t1 >= 48 h (no `if` needed). dT = sg*(Ta-Tm) is |Ta-5|.
- R1 (hot Tend <= 8) and R2 (cold Tend >= 2) as mode requirements. R3 (volume) and R4 (mass <= 22 kg) as laws `Vmargin`, `Mtot` and top-level requirements (judged by the stand, not pre-filtered by `where`).
- Objective INS.price + 6.5*m.

## APPROXIMATED
1. **PCM mass is not continuous.** The problem says "any real m >= 0". The continuous slot needs requirements affine in m; Tend has exp(-.../(Cp+m c)), so it is not. I used an integer catalog N and `computed m = N*0.01 kg` (N 0..1600, i.e. 0..16 kg; every option's mass cap is below 13 kg, so the range loses nothing). Not conservative for the OPTIMUM: the true continuous minimum is 6.367 kg / 109.3855 EUR, the stand reports 6.37 kg / 109.405 EUR (+0.02 EUR). Safe for FEASIBILITY: any m it earns is a real m. Only I checked the size of the loss (python, below). The stand's `optimal: true` means optimal on the 0.01 grid only.
2. **Hot/cold sign trick** (`sg`, `dT = sg*(Ta-Tm)`) replaces `|Ta-5|` and the two separate formulas of the problem. Exact identity (hot: T = Ta - dT e = 5 + dT(1-e); cold: T = Ta + dT e = 5 - dT(1-e)); only I checked it. The stand's cold-lane number matched my own direct cold formula, so it is exercised.
3. **Temperatures in C with `Tm = 5 C`** as a difference quantity (BRICKS treats C as no-offset); fine here because only differences appear and the 8 / 2 bounds are compared to Tend. Tend itself is "5 + difference".
4. Tolerances k "+/- 0.003" written as the range [0.035, 0.041] (exact, no loss).
5. Variant check `work_c01/v_alg.json`: I also wrote t1 and tau out by algebra, `(tend-t1)/tau = (tend*UA - f m L/dT)/(Cp + m c)`, so that each uncertain quantity occurs once. Not used in the final brick (the faithful form works). It gave the same optimum on the coarse grid.
- Dropped couplings: none. Independence of f, L, Cp, k, lanes is as in the statement. (Same L, Cp, k in both lanes are shared values in the real world; the modes give each lane its own box with no shared draw - this is sound because each lane is required separately.)

## COULD NOT EXPRESS
- **Continuous PCM mass with a non-affine physics**: no way to say "m any real >= 0" for this problem; only a grid. A tolerance-free optimal m would need the continuous solver to accept a nonlinear requirement.
- An `if`-free but verbatim "if t1 < 48 h" - expressed by max(0, ...), equivalent but not literally the text.
- Nothing else lacked a way to be said. `abs` is not in the law function list (BRICKS lists exp ln log10 atan tan sqrt pow min max), so |Ta-5| went through `sg`.

## DOES THE ANSWER LOOK RIGHT
My own python (`work_c01/mycheck.py`, floats, independent code; all 16 corners of k, L, Cp, f per lane):
- VIP-40 feasible for m in [6.367, 6.741] kg; at 6.36 kg hot worst = 8.0201 (fails), at 6.37 kg hot worst = 7.99008486 (stand: 7.99008486273, match to 9 digits) and cold worst = 2.89750847 (stand 2.89751, match).
- Vmargin at 6.37 kg: 43.008 - 8 - 6.37/0.92 = 28.0841 (match). Mtot: 8.6 + 180*(0.08 - 0.043008) + 6.37 = 21.6286 (match). (Note the envelope is 0.5*0.4*0.4 = 0.08 m^3; I first typed 0.064 in my own checker, which was wrong, then fixed.)
- Per option, minimum thermal m vs the caps (mine): EPS-80 needs 10.98 but volume cap 10.66; VIP-30 needs 9.21 but mass cap 8.16; VIP-20 needs 14.9 vs mass cap 9.7; PU-55 needs 12.5 vs mass cap 11.5; everything else needs more than 16 kg or is infeasible. So VIP-40 is the only feasible option, and the cost minimum is its lowest feasible m. This agrees with the stand's `optimal: true`.
- Not checked: monotone-corner assumption of my own check (reasoned: Tend is monotone in each uncertain quantity, so corners suffice - not proved); the stand's REFUTED reasons for the other 16 461 designs (I checked only the per-option feasibility above); the 0.01 grid optimum beyond N=637 vs 636 (I checked 6.36 fails, 6.37 passes).
- A trap I hit myself: I first wrote `Vin*1000` in the Vmargin law while declaring the unit L. The stand reads everything in SI, so the factor 1000 gave a wrong volume (19 564) with no unit error, and an EARNED verdict on a wrong design (EPS-80). The stand cannot catch a dimensionless factor error. I caught it only by reading the printed Vmargin.

## DOC GAPS
- Not stated: `abs` is not usable in a law (only `max`, `min`, etc. are listed); `sqrt` of an area and `max(0, time - time)` with units both work in practice.
- `computed` may be used in the objective: works, but the doc only says "laws, requirements, objective and where" - fine; and "integers" fields create `PCM.N` (not stated that N is available in `computed`, but works).
- Not stated how large a grid is practical: 16 462 designs = about 4.5 min with 2 modes; time seems to scale with designs judged, not with the combination count.
- Continuous slots: the doc says the objective and requirements must be affine in the amounts, but not what happens if they are not (BRICK ERROR or OPEN). I did not try, since the physics is clearly non-affine.
- `ties` section lists designs as "same objective" without saying they may be infeasible (it does say "not judged", but the layout invites misreading).
- Unit factor errors (L vs m^3) in a law are not caught; a note "SI inside laws: 1 L is 0.001" would help.
