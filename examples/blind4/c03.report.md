## EXPRESSED FAITHFULLY

- alpha = -ln(UVT)/(1 cm); att = exp(-alpha (R - r_q)); t = pi (R^2 - r_q^2) L / (Q/n); D = 0.7 * Puv*dim*a*f_foul*f_T/(2 pi R L) * att * t, written as in the statement (pi and L not cancelled by hand).

- f_T: the table is concave (slopes .0133, .0067, -.0053, -.0100), so the piecewise-linear curve equals the min of its four segment lines on 8..30 degC. Written as min(min(l1,l2),min(l3,l4)); I checked numerically it equals the table interpolation to 1e-16 on 8..30. The stand's `min` handles the non-monotonicity in T.

## APPROXIMATED
- Water temperature is a dimensionless given (the number of degC), unit "", not "C". Reason: the f_T lines need a dimensionless T; "C" is a difference unit and would make (0.08/6)*(T-8) carry a unit. Safe (nothing physical is changed), but the unit check on T is lost; only I check it.
- Requirement is LR >= 4 instead of D >= 40.04. The statement's 40.04 is itself a rounding of 40.0449 (4 ln10 / 0.23); the exact form is slightly stricter (0.011 %). With 40.04 literally dim_peak would be 0.99395 instead of 0.99407. Conservative; the stand checks it. (I did not run a 40.04 variant.)
- The "regimes" are three copies of quantities rather than modes. Equivalent; I chose it because modes cannot give a different continuous slot value per mode through a shared `define` in a way I could be sure of. Stand checks the copies, I checked I wrote them consistently (by python, see below).
- n is a design variable in the catalog, so "n <= 60" is not a requirement the stand judges, just the catalog range.
- Nothing else was rounded: all numbers exact fractions. The gap 0.00093 EUR is the LP/dual bound gap, not an approximation of the model.
