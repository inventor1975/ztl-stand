# c04 report: Workboat propeller + gear matched to a diesel engine (problem 4)

Final brick: `examples/blind4/c04.json` (REDUCED catalog: propellers P1-P3 x gears G1-G4, 12 designs). Generator and all scratch in `work_c04/` (gen.py makes any subset; check.py is my own solver).

## EXPRESSED FAITHFULLY
- Full propeller table (8 items) and gear table (5 items) in the generator; price objective `PR.price + GR.price` (EUR).
- Operating point as a real implicit root: unknown N (rpm, `search` [300, 2400]) with ONE implicit law. Hull-resistance table (9 knots, nested `if`, piecewise linear), engine torque table (nested `if`, 1000 below 800 rpm, 0 at/above 2150), rho, w, t, gear efficiency 0.97, 1 kn = 0.5144 m/s, K_T/K_Q linear in J with the +-3 % factors as toleranced givens, engine factor 0.96..1.00.
- The four conditions as modes: `bollard R1` (bol=1), `heavy R2`, `heavy R3`, `light R4`. Factors 1.30*1.05 = 1.365 (heavy) and 0.80*0.95 = 0.76 (light) as `fres` per mode.
- R1: Tnet >= 30 kN at K_T 0.97, K_Q 1.03, engine 0.96 (fixed values in the mode). R2: speed >= 9 kn at the same fixed unfavourable values. R4: N <= 2060 and tip speed pi n D <= 32 m/s at K_T 1.03, K_Q 0.97, engine 1.00 (fixed). R3: N >= 1900 over the WHOLE tolerance box (see below, this is my reading).
- Bollard pull and the tip speed are separate derived quantities with explicit laws.

## APPROXIMATED
1. **Hand elimination of the 2nd unknown (not conservative-by-construction; checked only by me).** The format has one implicit unknown per law, the problem has two (N, V). I solved the torque equation by hand for J (K_Q is linear in J: J = (J0/0.75)(1 - K_Qn/(KQ0*fKQ)), K_Qn = Te*i*0.97/(rho n^2 D^5)), got V = J n D/(1-w) explicitly, and left the thrust balance as the single implicit law in N. Algebra is exact (no rounding), but the stand does not check my algebra; it only judges the formulas as written. Verified by comparison with my independent solver (below).
2. **Bollard folded into the same implicit law** with a given flag `bol` (0/1) switched by `if(bol > 0.5, ...)` in both sides of the law (force form: Q_p/D on the torque side). `bol` is overridden per mode. Same exactness; checked only by me/numerics.
3. **Domain requirement I added:** `Jm = J0 - J >= 0` in every mode (the problem says K_T, K_Q are linear "for J <= J0"). It is not in R1-R4 but it is the stated validity range. Never decisive here (margins 0.38-0.9).
4. **Resistance beyond 13 kn extrapolated** with the last slope (17 kN/kn) and below 0 with the first slope: the table ends at 13 kn. It matters only for the root-exclusion search; all roots are at 8-11 kn.
5. **R3 tolerance reading.** R3 does not say which tolerances. I judged it over the whole box (3 factors independent), which is the "worst case" of the preamble, and stronger than R2's corner. R2 and R1 are at the stated unfavourable corner only (fixed values), as written.
6. **Search range [300, 2400] rpm** chosen by me from a scan (single sign change in my solver for all 40 designs and all 4 conditions at nominal corners). The stand finds "no root" as OPEN and "more than one root" as all branches, so a wrong range would show; none showed.
7. **Catalog reduced (the safe part is argued, the argument is mine):** the full 8x5 run was killed at 900 s (see TOOL OUTPUT). c04.json keeps only P1-P3 x G1-G4. The remaining designs with price <= 12300 (P4G1, P5G1, P4G2, P6G1, P5G2) were run one at a time (own bricks in work_c04/v_*.json), all REFUTED. All designs above 12300 cannot beat the earned 12300, so the optimum for the full catalog follows from: 15 cheaper designs REFUTED by the stand + P3G4 EARNED by the stand. This cross-run argument is mine, not one stand verdict; a full-catalog proof of "optimal: true" was NOT obtained in a single run. Ties: P5G2 is also 12300 and is refuted.
8. Units: speed is a dimensionless number in knots (`Vkn`), unit constants (1 rpm, 1 Hz, 1 N*m, 1 kN) are givens, so that the table comparisons are on pure numbers and the rpm-to-SI conversion is not left to the stand.

## COULD NOT EXPRESS
- Two simultaneous implicit unknowns (N, V): only by hand elimination (APPROXIMATED 1).
- "Only these tolerance corners" per requirement was expressible only through modes (one mode per tolerance set), which multiplies the work per design by about 4.
- A piecewise-linear table as data: only nested `if` in a define (8-9 levels); no lookup/interpolation primitive.
- A cost/time budget: no way to ask the stand for "stop at N seconds / report partial progress". A 900 s kill gives no output at all.
- Nothing about the physics itself was refused.

## DOC GAPS
- Implicit laws: BRICKS.md does not say what happens with two coupled unknowns (it says "one implicit law per quantity" but not that a 2-unknown system is unsupported); I only found out by reading the rule and eliminating by hand. A worked example of eliminating one unknown would help.
- `if` inside a `define` that contains the implicit unknown and is used in an implicit law worked, 9 levels deep, but the doc only shows a single `if` in a law. Not said whether nesting depth or `if(bol > 0.5, ...)` on a given is allowed on the implicit law itself.
- `rpm`: the doc lists the unit but not its SI value (1/60 Hz? 2pi/60 rad/s?). I avoided the question with unit-constant givens; others will not know.
- Mode override of a base `range` by a `value` (and vice versa) is only implied by the example; it worked.
- Cost: nothing says what one design costs (implicit root + corners + modes: 2 s to 180 s here) or that a kill at the time limit prints nothing; suggested guidance: put the cheapest mode first, expect about 20-180 s per design with a nested-`if` implicit law, and use `where` or separate bricks to bound the catalog. The mode order does matter little (the stand picks the worst failing mode, not the first).
- `report: "all"` costs the full 40 designs; not usable at this speed.
