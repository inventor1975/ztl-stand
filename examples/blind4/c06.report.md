# c06 report: Solvent recycle loop with purge and membrane modules (problem 6)

Final brick: `examples/blind4/c06.json` (generated by `work_c06/gen.py`, p grid k/10000, k = 1..400).
Verdict: EARNED, optimal: true (on the grid). Design: M4 x 3, no other modules, p = 0.0109, cost 138060 EUR/yr.

## EXPRESSED FAITHFULLY
- All 10 balances (5 for impurity 1, 5 for impurity 2) as linear laws in 10 derived concentrations. Impurity 2 is
  written out as its own block with removal 0, g_B = 0 (law `cBo2 == cBi2`), g_A = g2, c_m2 = 0.0001.
- Worst case over the uncertain data: g_A in [6,10], g_B in [3,6], c_m in [0.0002,0.0006], g2 in [0.10,0.18] as
  independent ranges; the stand holds for every point of the box.
- Module counts 0..4 per type (five slots, integer catalog), at most 8 in total (`where`).
- End-of-life data: capacity x 0.85 and rejection r_i - 0.05, as givens `kq`, `dr`, used in `computed`.
  Removal capacity r_eff*q = `Rcap` = kq * sum N_i Q_i (RJ_i - dr). The coefficient in the tank law is
  `((1-p)*FH - Rcap)`, exactly as stated.
- Treated-flow limit sum(EOL flow) <= 0.6 F_H, as a `where` on the exact value.
- Cost = module costs + p*F_H*8000*0.25, as the objective (nominal, exact inputs, so no tolerance issue).
- R1, R2 (two requirements), R3 as four requirements with bounds 0.008, 0.011, 0.015, 0.004.
- Units checked: "every law's dimensions agree".

## APPROXIMATED
1. **Purge fraction p is a 400-point grid (0.0001 .. 0.04), not a continuous variable.** Not safe as a statement
   about the true optimum: the stand cannot do a continuous p (see COULD NOT EXPRESS). The grid answer is a feasible
   design (a genuinely EARNED one), so it is conservative for feasibility, but it is 256 EUR/yr (0.19%) above the
   true continuous optimum, which I computed myself as p = 1/92 = 0.010870 (cost 137804). Checked: the stand proves
   the grid point; only I know the grid is coarse. "optimal: true" means optimal on the grid only.
2. **p = 0 left out of the final grid** (starts at 0.0001). With p = 0 the impurity-2 system has no steady state
   (no purge, no removal for impurity 2), and the stand returned OPEN for every p = 0 design ("the checker could not
   evaluate it: the laws do not determine every derived quantity") and then printed `optimal: false` ("86 cheaper
   design(s) undecided"). Dropping it by hand is safe physically (infinite accumulation violates R3), but the
   exclusion is mine, not the stand's. The earlier run with p = 0 included (0.001 grid) shows the OPEN behaviour.
3. **Interpretation of "treated flow <= 0.6 F_H"**: I used the end-of-life flow (0.85 q_i), since "modules run at
   full end-of-life capacity". If it was meant on new capacities the limit is tighter; the optimum (3 x M4, 1700 kg/h
   EOL, 2000 new, limit 2520) would still pass either way.
4. Costs: unit `EUR` for "EUR/yr" (no year unit in the list); the purge cost is in EUR via kg/h * h * EUR/kg. Safe,
   but the "per year" is only in the `why` text.
5. Per-type data (Q_i, r_i, cost) are separate givens (Q1..Q5, RJ1..RJ5, C1..C5), not catalog fields, because an
   integer catalog cannot carry extra fields. The pairing with counts is by my index; nothing checks that Q3
   belongs to slot M3.
6. Worst case: I did not state "worst at upper g_A, g_B, c_m"; the stand derived it (corners, "ZTL, exact at the
   corners"). No hand algebra.

## COULD NOT EXPRESS
1. **Continuous purge fraction with a linear-system model.** Continuous slots require every derived quantity
   defined explicitly (`X == ...`); with the balance system in implicit linear form the stand answered
   `BRICK ERROR: continuous choices need every derived quantity defined explicitly (X == expression) — version 1`
   (tested on a one-module-per-type variant, `work_c06/v_cont.json`). Also p multiplies the unknown c_H, so the
   problem is not affine in p anyway, so the LP route would not apply even with explicit definitions.
2. **"What happens when p = 0 and removal = 0"**: the singular case (no steady state, concentration grows without
   limit) is reported as OPEN with a generic "laws do not determine every derived quantity", not as REFUTED/unbounded.
   There is no way to state "no steady state means failure"; the design only blocks the `optimal` flag.
3. "Annualised EUR/yr" as a unit.
4. A paired per-item data block for integer-count catalogs (see APPROXIMATED 5).

## DOES THE ANSWER LOOK RIGHT
Checked with my own numpy solve of the same linear system (`work_c06/calc.py`, `calc2.py`) and an exhaustive search
over all counts and 41 p values:
- Same optimum on the 0.001 grid: 3 x M4, p = 0.011, 138900. Matches the stand.
- Guaranteed upper bounds at p = 0.0109 reproduced to 6 digits: c_T 0.00787418, c_Bi 0.00920751, c_Bo 0.01220751
  (impurity 1 at g_A = 10, g_B = 6, c_m = 0.0006); c_T2 = 0.00398899 = 1087/272500 exactly as the stand.
- c_T2 at p = 0.0108 is 0.0040254 > 0.004 (refuted, as the stand's grid says); at p = 1/92 it is 0.004 exactly. So
  R3 sets the purge floor (independent of modules, since impurity 2 has no removal); modules then only serve R1/R2.
- 3 x M4 at EOL: capacity 3*0.85*800 = 2040 kg/h <= 2520; removal capacity 1326 kg/h.
- Cost: 3*15500 + 0.0109*4200*8000*0.25 = 46500 + 91560 = 138060. Matches.
- Not checked: that no cheaper combination exists on the finer grid beyond the stand's own claim (the 0.001 grid
  was brute-forced by me, the 0.0001 grid only by the stand); the checker's corner enumeration is trusted for
  monotonicity (it is, by inspection: all concentrations are increasing in g_A, g_B, c_m, g2).

## DOC GAPS
- BRICKS.md does not say what happens with a singular system (p = 0, no removal): the answer is OPEN with a message
  that does not name the cause, and it also blocks `optimal: true`.
- Not stated: continuous slots with an implicit linear system fail with BRICK ERROR (only "every derived quantity
  defined explicitly" is mentioned, and not that the balance-system class is excluded).
- No guidance on running time of large grids (400 values x 3125 count combos: 8.5 min); `where` is cheap
  (1.2 M combinations excluded fast), the judged count was small, but 9313 designs were each tried at nominal.
- Unit list has no year; "per year" costs need a workaround.
- Integer catalogs carrying only one field is only visible by trying; per-type constants must be separate givens.
- `computed` used inside laws is allowed (works), but the doc says only "used like a given quantity in laws";
  fine, though first-time authors may doubt it.
