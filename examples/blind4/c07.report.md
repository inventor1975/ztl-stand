## APPROXIMATED
1. **Catalog cut (NOT safe as a "none exists" claim, checked only by me).** c07.json: all 7 NTC x 3 ADC x 3 classes, but pull-up only {10k, 22k} and R_par only "none": 126 designs (the where-filter removed 252 class mismatches). The true space is 7*3*(3*72*73) = 331 128 designs; one design costs 1-3 s in the stand, so the full space is ~10^2 h. What the stand establishes: all 126 fail. What backs the full space: (a) my own float scan of all 331 128 designs (work_c07/scan.py, model.py): 2546 designs meet R1+R2, all with N4, A12/A16, 0.1 %/0.5 % class; cheapest BOM 2.38 > 2.20, so R3 conflicts; (b) a relaxation brick checked by the stand (work_c07/stage2.json, 2.2 s): lower bound of the total error valid for ANY pull-up and ANY parallel resistor (R25 + B items exact, ADC item >= dx*4(T-1K)^2/B from the slope bound |dx/dT| <= B/(4T^2), pull-up item at R_NTC/R_par = 0). It refutes 58 of 63 (NTC, ADC, class) triples for every resistor value; survivors: N4+A12 at 0.5 %/0.1 %, N4+A16 at all three classes. All survivors have BOM >= 2.31 > 2.20 (N4 1.80 + A12 0.50 + >= 0.01). The slope bound and the "lower bound" argument are my hand derivation; the stand checks only the resulting formulas, not that the relaxation is a relaxation. I tested it numerically on 400 random designs x 321 temperatures: the bound never exceeded the actual error. With the survivor argument, "no design meets R1-R3" holds in the full space, but the stand did not prove it.
2. **Hand algebra for every error item (safe if right; checked by my python, not by the stand).** Writing "T_inferred(x') - T" literally with the nested chain made the stand useless (see TOOL OUTPUT). I used 1/T_inf = 1/T + delta/B with delta = ln(Rn_inferred/Rn), so dT = -T^2 delta/(B + T delta), and derived delta per item by hand: R25: ln(1+-tR); B: +-B*tB*(1/T-1/T0); pull-up: -ln(1 +- t(1+g)); parallel: -ln(1 -+ t g/(1+-t)); ADC: ln(rho) + ln((1-q)/(1-q rho)), g = Rn/Rpar, q = g/(1+g). My own python compared these with the literal chain on 300 random designs x 321 temperatures: max difference 2.9e-10 K (work_c07/check_algebra.py). The stand's checker "re-checks from the laws" - but the laws are the algebra, so it cannot catch an error in the derivation.
3. **R_par = none as a 1e12 ohm resistor** with the class tolerance, price 0. Its tolerance item is ~1e-10 K (the difference above includes it). Safe in size; it is a modelling trick.
4. **Vcc not in the brick.** Ratiometric, so Vcc cancels from x; I put Vsh = 3.6 V directly for the self-heating. The statement "Vcc anywhere 3.0..3.6" is a claim only I make.
5. **Self-heating at the nominal NTC** (other parts nominal), V_NTC = 3.6 x. Reading of the statement; the statement does not say which resistor values are used.
6. **"Error at its tolerance limit" = worse of the two signs** (max(|+|,|-|)) per item. Statement does not say which sign; this is the conservative reading.
7. **Piecewise R1 as two overlapping modes** (wide <= 1.0 on the full range, control <= 0.4 on 0..40). Equivalent (0.4 is stricter), boundaries 0 and 40 belong to the 0.4 band, as in the statement. Exact.
8. Temperature in K (law has 1/T); the statement's degC limits are converted by hand (253.15, 273.15, 313.15, 333.15). 
9. Tolerance fields (R25 tol, B tol, resistor class) are plain value fields, NOT tolerance boxes: the statement defines the error stack at tolerance limits, one at a time, not a worst-case box. Using the stand's tolerance mechanism would be a different (all-at-once) model.

## DOC GAPS
- No warning that a nested "T_inferred - T" costs cancellation: interval enclosure of both terms is ~T wide, so any piece of the box gives an error band of the same width as the quantity wanted. BRICKS.md says what a certificate does but not that its cost explodes (and `OPEN`/timeout, not an error) when a difference of two near-equal expressions of the same given appears. The fix is algebra by the author; the doc should say "express errors as small deltas".
- No per-design time or scaling guidance: 1-3 s per design, 80 K temperature box = ~10 s, the conflict analysis for 126 designs of the REFUTED case took most of 13 minutes; a 252-design brick was killed at 15 min without any partial output. Partial results on timeout would help.
- `guaranteed` for a certificate-proved quantity equals the requirement bound ("2/5"), not its true range; the doc's "guaranteed ranges" suggests the range.
- "the laws do not determine every derived quantity" OPEN message when a derived quantity is declared but unused (I hit it in a dropped stage-1 variant); not in section 8.
- Not stated: numeric `value` fields in E-series catalogs (my `cls`, `price`) are allowed and `where` can compare them (worked).
- `report: "all"` has no visible effect on a REFUTED brick (all designs are listed anyway).
- Named defines used inside defines worked; the doc says "earlier defines" - I did not test order sensitivity (I reordered once, while changing other things, so I cannot say whether order matters).
