# c09 report: Mountain-descent brakes, discs + pads + retarder for a bus (problem 9)

Verdict: EARNED. Design: front D6, rear D6, pad PA, retarder R1; total 5040 EUR; `optimal: true`
("every cheaper design was refuted in some mode"). Two other designs cost the same (D3/D4/PC/R2 and D4/D3/PC/R2);
the default run does not judge them. A `"report": "all"` run (work_c09/c09_all.json) judged all 900 combinations:
1 EARNED, 899 REFUTED, 0 undecided.

## EXPRESSED FAITHFULLY
- Four slots (F front disc, RR rear disc, PAD, RET) over three listed catalogs (6 discs, 5 pads, 5 retarders),
  900 combinations. Two slots draw from the same disc catalog, so F.Kf and RR.Kr are read from the same item list.
- The three regimes are three `modes` (m, grade, speed, length, ambient overridden). R1 and R2 are top-level
  requirements that hold in every mode.
- Laws as stated: gravity, rolling and air power; retarder power P40*v/40; P_f = max(0, ...); the 0.65/0.35 split with
  0.92 and /2; C_th = mass*460; the h(v) table; hA, tau, T_ss; T(t) with the real `exp`; T0 = Ta+30.
- Piecewise-linear mu(T) with five segments, constant below 20 and above 650, as nested `if` on the DERIVED disc
  temperature. Fav = 0.9*K-combination. F_req = m(4.0 + g s - 0.012 g) is a requirement bound expression.
- Objective 2*F.price + 2*RR.price + 4*PAD.price + RET.price, exact.
- g = 9.81 declared as its own quantity (built-in g0 is 9.80665, so I did not use it).

## APPROXIMATED
1. Tolerance reading (judgment call, not a hand-algebra change). "h x 0.80, mu x 0.92, K x 0.95" became one
   multiplier each, `fh in [0.8,1]`, `fmu in [0.92,1]`, `fK in [0.95,1]`, shared by all discs and axles. The table
   values are taken as the best case. The problem could also mean independent factors per disc/axle. Not safe to
   assume equivalent. Who checks: only me. In my python (work_c09/check.py) the earned design also passes with
   independent front/rear factors, so the verdict does not change. The stand did not run that variant.
2. h(v) above 15 m/s. The table ends at 15 m/s and two regimes run at 55 km/h = 15.28 m/s. I hold h at 62 above 15
   (lower h, hotter, so conservative). Linear extrapolation would be slightly cooler. My own python run with
   extrapolation gives the same optimum. Not checked by the stand.
3. "0.9*1000" in the Fav law. K is declared in kN, so the stand converts to N. I wrote `0.9*fK*fmu*(...)` without
   a second 1000. Numerically the same as the problem. The stand checks the units, so a missing or doubled 1000 would
   have been a unit error.
4. Dimensionless helper givens (`Tu`=1 C, `vu`=1 m/s, `hu`=1 W/(m^2 K), `vref`=40 km/h). These are needed because the
   stand's unit check rejects `12 + 16*v/5` (m/s next to a bare number). The values are exact 1 and 40, so they
   change nothing. The stand checks the units.
5. The `at the same T0 = Ta + 30 K` offset is a given `dT0`=30 K, with C and K treated as the same size of degree.
   Safe. Mine to defend.
6. No hand algebra, no bounds computed outside, and no couplings dropped. Everything else is as stated.

  fmu in {0.92, 1}, fK at 0.95: exactly one design passes, D6/D6/PA/R1 at 5040, same as the stand.
  The two 5040 ties (D3/D4/PC/R2 and D4/D3/PC/R2) fail R2 in my model too (margin about -26.8 kN).
- Witness check: the stand's first refuted design (D1/D1/PE/R0, mode c) has `by` = 297.032250762. My model at
  fh = 0.9 (middle of the range, which is the stand's witness) gives Tf = 897.03225076, i.e. 600 + 297.03225076.
  Match to all printed digits. The true worst corner is fh = 0.8, Tf = 962.1, so the witness is not the worst.
- Earned design: my worst case over the grid. Temperature: Tf at most 328.7 (a, fh=0.8), Tr at most 196.6.
  Force margin is the smallest in mode b: +2669 N at fh=1, fmu=0.92, fK=0.95. The stand's ranges contain mine
  (Tf [252.8, 367.3] around my [291.4, 328.7]), so they are sound but loose. The stand's outer margin in mode b is
  +1056 N, about 2.5x smaller than the true +2669 N. It was enough to EARN.
- Not checked: my grid is 21 points in fh and corner values in fmu/fK. The force margin is monotone in fmu and fK,

  variant in the stand.
- Obstacle reading (the REFUTED statistics above) shows the binding limits: small discs overheat the front disc
  (R1), and the stop force (R2) in loaded-fast needs high-K big discs with a pad that stays warm.

## DOC GAPS
- `^` in a define is a BRICK ERROR ("BitXor is not allowed here"); BRICKS.md only mentions `a**b` in the functions
  paragraph. Define and law syntax should say "use **" next to the operator list.
- BRICKS.md does not say whether `if(...)` conditions may compare a DERIVED quantity (I used `Tf <= 100*Tu`; it
  worked). It also lists `ifpos` in the error message but not in the doc.
- It does not say that `max` works inside `define`; it worked.
- Not documented: a define referencing a mode-overridden given is re-expanded per mode (it was, correctly); and what
  prints on `units` when everything is checked.
- The doc says "a bare number in a sum takes its partner's unit" but not that a bare number beside a quantity in a
  product/ratio does not (needed the `Tu`/`vu`/`hu` helpers).
- "Requirement bound may be an expression" with mode-overridden givens (`m*(4.0+g*sl-...)`) works but is not stated.
