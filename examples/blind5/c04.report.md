# c04 report: gravity sewer in two reaches (problem 4)

Final brick `examples/blind5/c04.json` (generated by `work_c04/gen.py`, run with `CLAMP=1 SUB="PVC,CONC,PE|250,300|0.0035,0.005"`). Verdict on it: EARNED, PVC, (D_A, S_A) = (250 mm, 0.005), (D_B, S_B) = (300 mm, 0.0035), cost 191.573 kEUR, `optimal: true` — but ONLY inside a catalog I cut down by hand (see APPROXIMATED 1). The full catalog of the problem was NOT decided by the stand within 900 s.

## EXPRESSED FAITHFULLY
- Three materials as one catalog: n as an absolute `range` (0.0095-0.0115 etc.), k, v_max. Material is ONE slot `M`, so both reaches use the same material and the same n value. Requirements R1-R3 are per reach and share no quantity between reaches except `M.n`, so one n for both reaches gives the same verdict as independent n per reach.
- Diameters {250, 300} and slopes {0.0035, 0.005} per reach, as separate slots DA, SA, DB, SB (reduced sub-lists; the original lists are in APPROXIMATED 1).
- Partly full circular pipe Manning law, with the depth as an implicit root (`search`) for each of the four cases (A dry, A storm, B dry, B storm). Velocity = Q/A_f, depth ratio y/D, geometry exact (no small-angle shortcut).
- R1 (v >= 0.60 at Q_d, each reach), R2 (y/D <= 0.70 at Q_pk, each reach), R3 (v <= material max at Q_pk, each reach), R4 (invert depth at end of B <= 5.0 m, as a derived quantity `dend = H0 + S_A L_A + S_B L_B`), R5 (D_B - D_A >= 0). All six judged by the stand, for every n in the range.
- Surcharge condition ("Q exceeds the flow at y/D = 0.938 -> fails") as a requirement `g <= 1` per reach and flow (see APPROXIMATED 3 for how).
- Cost: reach cost = L (k (D/200)^1.3 + (20 + 28 d_avg)(1 + D/1000)), d_avg from the exact slopes, objective in kEUR; units checked ("every law's dimensions agree").
- Slopes of 0: not in the final catalog (see below).

## APPROXIMATED
1. **Catalog cut by hand (NOT safe for the claim "this is the optimum of the problem"; checked by me only).** Full problem: 3 x 5 x 7 x 5 x 7 = 3675 combinations. The final brick has 3 x 2 x 2 x 2 x 2 = 48. I chose D in {250, 300} and S in {0.0035, 0.005} AFTER my own float scan (`work_c04/check.py`, scipy Brent root, n at 21 points) had told me where the optimum is. So the stand's "optimal: true" means "optimal among 48", and the stand did not find this design in the full space. What the stand did check on the way: in a 675-design pruned catalog (slopes {0.002, 0.0035, 0.005}, all D, all materials; `work_c04/full675.json`) it had REFUTED the 300 cheapest designs by 850 s with none earned, then I stopped it (the limit). My scan says that catalog has 341 designs cheaper than the optimum, so the stand covered ~88 % of the cheaper ones and did not finish.
2. **Slope pruning by arithmetic (safe, mine).** S = 0 dropped because the statement calls it inadmissible; S >= 0.008 dropped for R4 (1.5 + 0.008*420 = 4.86 m at the end of A, plus S_B*380 > 0 with S_B >= 0.002 gives > 5.0; S_B >= 0.008 gives 1.5 + 0.84 + 3.04 = 5.38 > 5.0). This is exact and only removes designs that R4 refutes, but the stand never saw them.
3. **Surcharge clamp (conservative, checked by the stand's own refutations, but a trick).** Without it a surcharged design has no root in `search` and the stand says OPEN ("no root in the search range ... for any value of the box"), not REFUTED. 3 of the first 9 designs in a probe were OPEN that way, each costing ~56 s, and they would block `optimal`. Fix: the left side of the Manning law is `min((Q n)^6, 0.99*K6)` where K6 = A^6 R^4 S^3 at y/D = 0.938 (`search` upper end t = 3.8896 = tan(theta/4) at y/D = 0.938), so a root always exists, plus the explicit requirement `(Q n)^6 / K6 <= 1`. For a design with Q at or below 0.99^(1/6) = 99.83 % of the 0.938 capacity nothing changes. Between 99.83 % and 100 % the reported depth is wrong (clamped, y/D around 0.9), but R2 (y/D <= 0.7) refutes there anyway, so the verdict cannot change. For an EARNED design the clamp is inactive (g in [0.002, 0.04] vs 1).
4. **Manning raised to the 6th power.** `pow(R, 2/3)` is refused ("m to a power that is not a constant": `2/3` is not read as a constant). I wrote (Q n)^6 = A_f^6 R^4 S^3. Same root since all sides are positive; exact, no rounding. Cost: the implicit law is steeper, which may slow the stand (unknown).
5. **Trig by substitution.** No `sin`/`cos`. I used t = tan(theta/4): theta = 4 atan t, sin theta = 4t(1-t^2)/(1+t^2)^2, y/D = t^2/(1+t^2). Hand algebra, exact identities; I checked them numerically only through the final agreement with my float code (see below). The stand does not know these are the problem's formulas; the `source` strings say so.
6. **Search lower end t = 0.01** (y/D = 1e-4). The statement has no lower limit; with Q_d 6.5 L/s the roots are far above. Unchecked for steep slopes (not in the final catalog).
7. **Price factor (D/200)^1.3 precomputed outside** as catalog field `pf` with 12 significant digits (e.g. 1.33654324999). Only the objective is touched (relative error ~1e-12), no requirement. Reason: `pow(x, 1.3)` in the objective over 3675 combinations looked slow; I never separated that effect from the product-size effect below, so it may have been unnecessary. Checked by me only. The stand's objective 748332761441/3906250000 = 191.573186929 kEUR equals my float 191573.18692875846 EUR/1000 to all digits shown.
8. **The 0.938 limit is rounded in the search end**: t = 3.8896 gives y/D = 0.937998 instead of 0.938. Irrelevant for verdicts (R2 at 0.7 is far stricter).

## COULD NOT EXPRESS
- `sin`, `cos`, `acos`: the problem's theta formulation had to be rewritten with tan(theta/4).
- A non-integer exponent written as a quotient (`2/3`) — see APPROXIMATED 4.
- "Surcharged = condition fails" as a verdict: the stand treats "no root of an implicit law" as OPEN, never as a failed condition. I had to add a clamp.
- Admissibility of a design from exact data as a stated condition: R4 and R5 can be requirements (judged) but I could not make S = 0 ("inadmissible") a requirement because the implicit law has no root there; it had to be removed from the catalog (or `where`).
- Mixed-radix choice "for each reach a (D, S) pair from product lists" is expressible only as separate slots, so the raw design count is the product 3675; see DOC GAPS about the product size.
- Optimality claim over the full space within the time limit: not reached (see TOOL OUTPUT).

## DOC GAPS
- BRICKS.md says "The stand tries every combination ... the count is the product of the catalog sizes" but does not warn that a product of about 2000+ made the run silent for 16 minutes (see TOOL OUTPUT). Progress goes to stderr only; with `| head` it is lost.
- Not documented: `timeout ... heavy` leaves the stand running past the limit.
- "No root in `search` for a design: that design is OPEN" is documented, but not the consequence: a physically failed design (surcharged pipe) becomes OPEN, blocks `optimal`, and costs ~1 min each. A documented pattern for "no solution = failed condition" is missing.
- `pow(x, 2/3)` does not work although "constant exponent (integer or not)" is documented; `1.3` works. The doc should say that only a decimal literal is a constant.
- `sin`/`cos` are listed as nonexistent; a hint that `atan` plus tan(theta/4) covers circular segments would have saved time (documented only by the t15 lens example I did not study).
- `where` is documented as removing combinations from the design space; it did not reduce the startup time on large raw products.
- A nominal-failing design is described as cheap ("drops a design whose nominal point already fails") but a nominal failure that needs the exact implicit solve took ~0.3-2 s, and designs that pass nominal but fail in the box took 20-90 s each; the docs give only "20 s per design" for nine toleranced quantities.
