Scratch/variants/outputs: `examples/blind5/work_c06/` (`full_R4req.json` = the first, fully faithful brick; `v5/final.out` = final output; `v6.json` = B=2.4 check).

## EXPRESSED FAITHFULLY

- Every law as written: W, N_t, e, B', q, Nq (exp, tan, pi), Nc, Ngamma (tan(1.4 phi)), q0 as a 2-case `if`, gamma_b as a nested 3-case `if` on the derived B', q_u, FS, settlement. Units on everything (checked: "every law's dimensions agree").
- `valid: "Bp > 0"` on the q law (added; the text does not state it, but it is a safe domain guard; stand proved Bp in [2.19, 2.32] for the B=2.4 check).
- R1 (FS >= 3), R2 (s <= 25 mm), R3 (e <= B/6, bound `FB.B/6`) as requirements, for all admissible values.
- 8 widths x 5 depths as two listed catalogs, 40 combinations; objective `c72*B + c28*(B+0.6)*Df + c32` with the three coefficients as unit-carrying givens (EUR/m^2, EUR/m^3, EUR/m). (Objective never used: no design earned.)

## APPROXIMATED
1. **R4 (B <= 2.0 m) moved from a requirement to `where: ["FB.B <= Bmax"]`.** Reason: R4 is on a catalog value, not derived. I first made it a requirement through a dummy derived `Bw == FB.B`; then the run never finished (see TOOL OUTPUT) because `minimal_conflicts` judges all 2^4 subsets and the subset without R4 makes B=2.4 a tight, heavy proof. Effect: B=2.4 is not "judged and refuted by R4", it is removed from the design space (`excluded_by_where: 5` = the five 2.4 combinations). Verdict-equivalent here (exact test on an exact value, safe), but the output no longer lists R4 as a violated requirement, and R4 cannot appear in the conflict sets. Checked by: only me (the `where` is "nothing in them is judged").
2. **Degrees as a bare number.** `phid` is a dimensionless range 25..29, converted by `define phi = phid*pi/180`. `deg` is not in the unit list. Unit checking of "angle" is therefore absent (checked only by me). pi is the stand's 1e-15 bracket, so every angle has a 1e-15 slack (negligible; the stand reports pi as a "contributor" of ~6e-15).
3. **`max(Df - 0.45, 0)`** done as `computed: Dbf = max(FD.Df - tf, 0*tf)` (exact, per design; the bare `0` was a unit error: "max of different units"). Exact, safe, the stand does the arithmetic.
4. Constants 0.3 and 1.12 as givens `nu`, `Is`; `(1 - 0.3^2)` written `1 - nu*nu`. Pure renaming.
5. Settlement in mm: law has `E` in MPa, q in kPa, s unit mm; the stand does the scaling (unit-checked).
6. Only the **absolute** |M| is modelled (as the problem states). No sign enumeration needed. Not an approximation.

- Nothing about the physics itself was inexpressible; the stand accepted tan, exp, nested `if` on a derived quantity, and branch on `zw` vs `Df`.

## DOC GAPS
- Nothing says that `timeout ...` does not stop the stand (SIGTERM ignored) and that the output is written only at the very end, so a killed run leaves nothing.
- minimal_conflicts cost: BRICKS.md says up to 2^n runs but not that the subsets without a hard requirement can be a heavy EARNED proof, so adding a "boundary" requirement can multiply run time ~5x or more (here: > 57 min vs 98 s). No switch to disable it.
- `max(x, 0)` with a dimensional x fails ("max of different units"); BRICKS.md says a bare number in a sum takes its partner's unit but does not say it fails inside `max`/`min` (workaround `0*tf`).
- A requirement `quantity` must be derived is stated, but the standard way to bound a catalog field (`where`) is not mentioned for requirements-like constraints; the effect (excluded vs refuted) is only implicit.
- No degree unit; `rad` is listed but trig functions take dimensionless arguments, so it is unclear whether `rad` is dimensionless.
