## EXPRESSED FAITHFULLY

- Spot availabilities 800/800/800/300 and the 118 EUR/year lease price, as givens.

- R2 (worst-case annual cost <= 355 kEUR) as `Cost <= 355` in kEUR, with the law written in EUR. The unit scaling worked.
- Objective: minimize the worst-case `Cost` (`"case":"worst"`).

## APPROXIMATED
1. **B is not continuous.** It is a list of 104 values: a 50-position grid from 0 to 3200, plus the exact breakpoints `N_q(top) - cap - sc` (rational numbers such as 19750/11).
   - Not conservative for "no choice exists" over continuous B. The stand refutes only the listed B values.
   - I checked the continuous claim myself in `ref.py`: cost is piecewise linear in B, so I enumerated all breakpoints for the 4 tiers. The minimum is T3 at B = 19750/11 = 1795.45 with 367.195 kEUR > 355. The stand does not check this argument.
   - Why: the continuous-slot mode needs an affine objective and affine requirements, and min/max are not affine.
2. **R1 is hand-algebra, not the literal inequality.**
   - The literal margin `B+F+S-N >= 0` came out OPEN. The interval reading proved Mmin in [-944, 944], because N and F cancel in the interval arithmetic.
   - I rewrote it as uncovered need `U_q == max(0, N_q - B - cap - Sc_q)` with `Mmin == max(U1..U4) <= 0`.
   - This is exactly equivalent: coverage is possible if and only if N <= B + cap + Sc.
   - The stand checks the law and the bound, but not that my rewrite equals the literal R1. I checked that by hand and against the python reference, which agree on the 200 listed designs of the main brick and the 132 of the B 1700..2700 sub-brick.
   - Side effect: R1 becomes one requirement, "every quarter", not four.
3. **S_q is written in closed form**, `min(Sc_q, max(0, N_q - B - cap))`, instead of `N - B - F`. This is algebraically identical. The literal form (with F as a derived quantity inside) gave Cost in [319, 494], too wide to decide anything.
4. **R3 `B <= 3200`** needs a derived quantity (`Bchk == OWN.B`, bound `Bmax`), because requirements must name a derived quantity. The B grid also stops at 3200. R3 is therefore double-enforced and the stand checks it.
5. **"S_q <= availability" and "F_q <= cap"** are true by construction (the min), not separate requirements. They are not independently checked.
6. Worst case is not hand-substituted. I gave the stand the ranges and it takes the worst. The "worst is at the top" claim in the problem was not used by me; the stand's bound agrees with it (see below).

## COULD NOT EXPRESS

## DOC GAPS
- BRICKS.md never warns that interval reading of a derived quantity loses all correlation: `B + F + S - N` with `F = min(cap, N - B)` is in truth non-negative but is read as [-944, 944]. The OPEN reason ("extreme may lie inside the box") points at the wrong cause; the doc should say what rewriting makes a derived quantity decidable (single appearance of each uncertain given, monotone form).
- For `"case":"worst"` the doc does not say what happens when every design is REFUTED (no objective is reported, which is fine, but it is not stated).
- `designs` listing cap 200: "earned first, then open, then refuted" does not say which refuted ones survive the cut, so R2-failing designs can vanish from the report.
- "continuous" is documented as affine only; there is no hint about how to approximate a piecewise-linear continuous choice (grid + breakpoints, which I did).
- `by` for a REFUTED design is at the witness (nominal or corner), not the worst point. This is documented in the output but easy to misread as the margin: for T3 B=19750/11 the reported R2 overshoot was ~1.9 kEUR, true 12.2.
- A requirement must be on a derived quantity, so a bound on a catalog field (R3) needs a dummy derived quantity; the doc says only "must be derived".
