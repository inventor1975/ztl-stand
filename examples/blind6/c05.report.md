# c05 report: workshop compressed-air line, compressor + dryer + main pipe (problem 5)

Final brick: `examples/blind6/c05.json` (one flat brick, three modes S1/S2/S3, 5x4x5 = 100 designs; generator `work_c05/gen_flat.py`).
Also tried, in `work_c05/`: the same chain as components (`c05_components.json`, S3 only).

## EXPRESSED FAITHFULLY
- All three catalogs as listed items with units (FAD L/s, cut-in/cut-out bar, price EUR; Qr, dp_rated; d mm, price EUR/m). One compressor, one dryer, one pipe diameter = three slots.
- Tool flows QA 14..18 and QB 8.5..10.5 as ranges ("any value"), leakage 1.5..2.5 as ONE given used by every law, fouling f 1.0..1.7 as ONE given, the dryer law dp = dp_rated (Qt/Qr)^2 f, the pipe/hose law with pow(Q/Qu, 1.85) kept as a law (not pre-evaluated), Qt = running tools + leakage per situation, tool inlet = (cut-in - 0.15) - dp_dryer - dp_main - dp_hose, each hose carrying only its own tool's flow.
- S1, S2, S3 as three modes (each with its own Qt law, hose laws and R1 requirement); R2 (Qt <= facfad*FAD with facfad in [0.94, 1.00], so the least favourable end 0.94 is what is judged), R3 (Pnf = cut-out + 0.15 <= 8.5 and <= 9.0), R4 (Qt <= Qr) as requirements; R2/R4 only in S3.
- Objective: minimize C.price + D.price + P.price*Lmain with Lmain = 180 m a given (price per metre x length, unit-checked in EUR). Units checked on every law (the stand said "checked").

## APPROXIMATED
1. **Per-design coefficients computed outside the laws** (`computed`): PABS = cut-in - 0.15 - 0.5 + 1.013 and CMAIN/CHA/CHB = 1600*L/(d^5*PABS) are exact per-design values; the laws only contain `CMAIN*pow(Qt/Qu, 1.85)`. The constant 1.6e3 is a given KP with unit bar^2 and the lengths/diameters are divided by unit givens (1 m, 1 mm, 1 L/s) so the empirical law passes the unit check. This is exact fraction arithmetic and not a loss, but the formula text is mine; the stand does not check that I transcribed 1.6e3, d^5 and p_abs correctly. Only I checked it (python, below). Safe.
2. **Cut-in / cut-out tolerance**: not modelled as a toleranced quantity. I put in the two extremes the problem itself prescribes (lowest cut-in = nominal - 0.15 for R1 and for p_abs, highest cut-out = nominal + 0.15 for R3), as exact numbers with a given dtol = 0.15 bar. "The band may sit anywhere inside the tolerance" is therefore not judged by the stand; that the extremes are the worst cases is my argument (the problem fixes p_abs at the lowest cut-in anyway). Safe as stated in the problem; checked only by me.
3. **Idle tool in a mode**: the format requires every derived quantity to be determined in every mode, so in S1 I added `dphB == 0*dpdry` and a PinB law, and the same for A in S2. No requirement is put on an idle tool's pressure. Faithful in meaning (no flow, no hose drop), a trick in form.
4. **Leakage and f are drawn independently per situation** (modes are judged separately). All requirements are per situation and monotone, so this does not change the answer (the stand's S3 worst case is the same as what a joint draw would give). Safe.
5. **Components version (not the deliverable)**: S3 only (S1/S2 are dominated, my argument, not checked there); the compressor's and dryer's ratings R2/R4 became the contract's `assume` range [0, 0.94 FAD] / [0, Qr] (hand-written per file), so a too-small compressor comes out OPEN ("leaves assume") instead of REFUTED; hose/pipe flow assume starts at 5 L/s, because with 0 the contract was undecidable (pow(0, 1.85)); main-pipe price 180 m x EUR/m multiplied by hand in the candidates' `fields`.

## COULD NOT EXPRESS
- A quantity that exists only in some modes ("tool B is absent in S1"): the dummy laws of item 3 are the only way.
- The cut-in/cut-out switching band as a pair of independent toleranced quantities that the stand sweeps (the problem fixes the used values, so I did not need it, but a variant like "p_abs follows the actual cut-in" would need laws with a toleranced catalog field in a divisor, which the stand would then have to correlate with the pressure).
- Components with situations: a system has no modes, and one chosen compressor/dryer/pipe must serve all three situations, so S1/S2/S3 cannot be three instances of the chain (each `choose` would pick independently). Only S3 fits; the other situations need the flat brick.
- Anything about the real physics beyond the stated empirical law (compressibility, pressure varying along the pipe): not asked, nothing in the format for it either.

## DOC GAPS
- Modes: BRICKS.md does not say that every derived quantity must be determined by the laws in EVERY mode, including quantities of an absent device; the error message appears only at run time.
- `"bands": "arriving"` (section 7d) does not say where to write it. At the system's top level it does nothing (silently; same result as without); inside each `interface.inputs.<name>` it works. I found this by trial.
- Section 7d does not say that a component's `assume` must also cover the ratings: a rating requirement violated somewhere in the assumed range makes the whole band "no guarantee (REFUTED)", so ratings must be turned into the assume range by hand, and the system then reports OPEN rather than REFUTED.
- A component's flow input with assume starting at 0 and `pow(Q, 1.85)` gives "could not be decided" with no hint about the zero.
- Section 2 says computed "stays exact: no exp/ln" but does not say whether `pow` or integer powers work; I wrote d^5 as five factors. Names of `computed` values in laws are allowed (used here) but only implied by "used like a given quantity in laws".
- The skeleton says `"stand": "ztl-stand/1"`, the examples use `"universal-stand/1"` and the output prints `ztl-stand/1`; both inputs accepted.
