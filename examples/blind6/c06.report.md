# c06 report: phenolic wastewater, countercurrent extraction + carbon bed (problem 6)

Verdict of the final brick `examples/blind6/c06.json`: EARNED, E3H + SC + G1200, S = 12409200/9026443 = 1.37476 m3/h (1.375 to three decimals), 5-year cost 270.657 kEUR, proved lower bound 270.653 (gap 0.0043, so `optimal: false`).
The final brick holds the N = 3 extractors only (E3, E3H). The whole problem did not fit in ONE brick (see APPROXIMATED 1). E2 and E4 were judged in separate bricks.

## EXPRESSED FAITHFULLY
- Catalogs as listed: 4 extractors (N, eta, price), 3 solvents (cS), 3 beds (m, price). The continuous solvent flow S is a continuous slot `SS`, 0.5 to 1.8 m3/h.
- The stage balances are written literally as a linear system in the unknowns, with S, K_eff and rho in the coefficients.
  - Stage N: `F*(z2 - z1) == S*Keff*(z1 - rho*z3)`. Stages N-1 and up: `F*(z_{j+1} - z_j) == S*Keff*(z_j - z_{j-1})`. The feed-end stage uses `cF` as x_0.
  - Here z_j is the stage numbered j from the SOLVENT end, so z1 = x_N and z_N = x_1. This is only a renaming.
  - `rho` is ONE quantity shared in the recycle term. `cF` is ONE quantity.
- K_eff = eta * K(T), in a `define`: `Keff = EX.eta*SV.Kt`. The same Keff is used in every stage, so T is shared.
- y_in = rho*K_eff*x_1 is inside stage N's equation. y_1 = K_eff*x_1 as `y1 == Keff*z3`.
- Raffinate `xN == z1`. Discharge `Dis == (1-e)*xN`. Bed life `Life == qc*BD.m/(F*xN*Hmo)` with `Hmo` = 700 h given. The unit check passes: the dimensionless result is months.
- Requirements R1 (xN <= 0.12), R2 (Dis <= 0.006), R3 (Life >= 2), R5 (y1 <= 8.5) as stated.
- R4 as a requirement on the amount itself: `{"quantity": "SS.x", "op": "<=", "value": "Hs*F"}` with `Hs` = 1.2 given. The stand accepted this and reported `SS_x_req`.
- cF 6.0 to 7.5 g/L, rho 0.02 to 0.04, q 0.10 to 0.14, e 0.90 to 0.96 are given ranges (independent).
- Objective: `EX.price + BD.price + Yrs*Hyr*SS.x*SV.cS` in kEUR, with Yrs = 5 and Hyr = 8000 h given. The units are checked (kEUR with EUR/m3 x m3/h x h).
- The question "choose extractor, solvent, bed and S at minimum cost" is answered by the stand's continuous-slot search, with proved lower bound and gap.

## APPROXIMATED
1. **One brick for the whole problem was not possible: I split by number of stages N. The splitting is mine, not the stand's.**
   - The system has N unknowns, so E2, E3 and E4 need different law sets, and a brick has one law set.
   - Tried as one brick: four unknowns always, with exact 0/1 stage flags (`computed`) that turn unused stages into `z_j = cF`. The solvent-end recycle term picks z_N by flags. This is `work_c06/c06_flat4_full.json`, 36 combinations.
   - It did not finish design 1 of 36 in 15 min (killed by me at 15 min 24 s, see TOOL OUTPUT). The first design is an infeasible one (E2), so even refuting it was too slow. Alone, the N = 2 flagged combination took 126 s; the exact N = 2 brick took 1.4 s.
   - Tried the hand-solved closed form (`work_c06/c06_closed.json`, N via exact flags in polynomials, no system): ONE combination (E3H, SC, G1200) was not done after 10 min. Killed. This form also needs my hand algebra.
   - So the final c06.json is the exact-N brick for N = 3 (E3 and E3H, 18 combinations, 75 s).
   - E2 (N = 2) and E4 (N = 4) were judged by separate bricks (`c06_n2.json`, `c06_n4.json`) and by 36 single-combination bricks (`work_c06/sweep/`, 311 s in total). The union of those runs is the answer to the whole problem. Only I combine them; the stand never sees the three together.
2. **T is replaced by the range of K(T), computed outside (safe: outward rounding, checked only by me).**
   - The brick has no T. Each solvent has a catalog field `Kt` with `range` [K25*exp(-5a), K25*exp(10a)] for T = 30 and 15 C. They are computed in python (50-digit Decimal), then rounded OUT at 1e-9 (e.g. SC: 9.582194625 to 18.819746226).
   - This is exact for the problem as stated, since K is monotone in T and T enters only through K. The rounding widens the box by under 1e-9 relative, so it is safe (conservative).
   - Only I check the exp values (python). The stand sees only the interval.
   - Reason: `exp(...)` inside a `define` that multiplies derived quantities was refused (BRICK ERROR, quoted below).
3. **R4 is also enforced by the catalog range of S (upper end 1.8 = 1.2 F exactly)**, in addition to the explicit requirement. Both say the same thing; the explicit one is judged.
4. **Months are dimensionless.** `Life` has unit "" and 700 h is a given `Hmo`. Equivalent to the statement; checked by units.
5. **Ordering and the optimum.** The stand's S = 1.37476 sits 1.9e-5 above the true limit S* = 1.374744 (where y1's worst case is exactly 8.5; I computed it in python). This costs 0.0034 kEUR. The stand's own `gap` is 0.0043 and says `optimal: false`. The stand does the "hair inside" step; it is not my change, but the reported S differs from the exact optimum in the 5th decimal. The three-decimal answer is the same, 1.375.

## COULD NOT EXPRESS
- **Different stage counts in one system of laws.** No way to say "N unknowns where N is the extractor's field". The workaround (flag-padded system) is correct but about 100x slower; the closed form is slower still.
- **A temperature coefficient inside a linear system.** `exp(-a(T-Tref))` as a coefficient of derived quantities. Law refused (see TOOL OUTPUT). Worked around by pre-computing the K range per solvent. The link "T is the same value in every stage" survives only because T became one range field per solvent.
- **A cross-slot join of two catalog values into a toleranced range.** `Keff = EX.eta*SV.Kt` works as a define, but the exp(T) part had to be done by hand; I did not find a way to keep T itself as a given and still use the linear-system path.
- Months as a unit (no `month` in the unit list; handled by Hmo).

## DOC GAPS
- BRICKS.md section 4 says "given and catalog quantities may multiply" derived quantities in a linear system. A `define` that contains a function (`exp`) is NOT accepted there, only as `X == expression`. The doc does not say a function in a coefficient leaves the linear class. The error text names the law but not the cause.
- Nothing says how to handle a catalog item that changes the number of unknowns (different N). The flag-padded form is valid but extremely slow; the doc does not warn. The doc's c06 line (t36) speaks of up to 6 unknowns and does not say what padding costs.
- "Time limit mandatory" in the task: `timeout 900 ~/bin/heavy ...` did not stop the stand (see TOOL OUTPUT). Whoever relies on it will have a stuck run.
- Section 2 (continuous) says the bound is PROVED and `gap` is the distance to the optimum; it does not say that a negative gap or a note "ZTL did not accept the dual certificate" can appear next to EARNED, nor that a combination may then report another combination's data. Here the EARNED was false.
- Examples use `"stand": "universal-stand/1"`, BRICKS.md `"ztl-stand/1"`. I used the latter and it ran, so both seem accepted; the doc does not say.
- A requirement on a continuous slot's amount (`SS.x <= Hs*F`) works but is not documented in the continuous section.
