# c07 report: stormwater detention pond (problem 7)

Verdict: **REFUTED** — no admissible design exists (all 5 plates, whole box A 100..610, H 0.8..2.0). 24.8 s.
`examples/blind6/c07.json` is a flat brick (no chain of devices, so no components; no limiting value, so no `find`).
Design = 3 slots: plate (listed catalog, 5 items) + two continuous slots (A, H). Six storms are written out as six
sets of quantities in one brick (C and Cd are single quantities shared by all, the six intensities are independent).
Generator and scratch files: `work_c07/` (`gen.py` makes the brick; `c07_closed.json` is the same file).

## EXPRESSED FAITHFULLY
- Ac, C 0.70..0.80, Cd 0.58..0.64 (one quantity each, shared by all six storms), g = 9.81 (own given, not g0),
  six independent intensity ranges in mm/h, six durations t, pond price 0.12 kEUR/m3 x A x H + plate price.
- Qin = C i Ac as a define with i in mm/h and no 3.6e6 typed (the stand scales the unit).
- Plate table (d mm, price kEUR) as a listed catalog; A and H as continuous catalogs with the site limits as their
  ranges; objective `cp*PA.A*PH.H + PL.price` in kEUR (bilinear in the amounts, as stated).
- Qpeak = Cd Ao sqrt(2 g h) as stated; R1 (3 storms), R2 (3 storms), R3 as margin `M = H - h` >= 0.30 m (3 storms),
  R4 as a requirement on the catalog field `PL.d >= 80` (mm). Units: "every law's dimensions agree".
- "Every uncertain quantity anywhere in its range independently" = the stand's for-all over the box.

## APPROXIMATED
1. **Storage balance solved by hand for h** (not safe by itself; checked only by me, see below). The stated law
   A h + Cd Ao sqrt(1.2 g h) t = Qin t is quadratic in s = sqrt(h). I wrote the positive root
   `s == (sqrt(kk^2 + 4 A Qin t) - kk)/(2A)`, `h == s*s`, `kk = Cd Ao sqrt(1.2 g) t`. The root is unique for A > 0 and
   the law's uniqueness remark holds, so it is the same h, but the stand does not know that the root solves the
   balance: nobody checks my algebra but me (I verified it numerically, see DOES THE ANSWER LOOK RIGHT). The faithful
   form (implicit law with `search`) was written first and REFUSED, see COULD NOT EXPRESS 1.
2. **R4 and R5 are not checked as "requirements on the world".** R5 (A <= 610, H <= 2.0) is the continuous catalog's
   box, so it is not in `minimal_conflicts` and cannot be named as relaxable by the stand. R4 is a requirement
   (`PL.d >= 80`) but the tool did not get as far as listing conflicts (below).
3. **No conflict analysis from the stand.** `minimal_conflicts` was skipped: "10 requirements: subsets over 8 not
   enumerated". My regroup into 3 requirements via `max`/`min` laws (R1 = max of 3 peaks, etc.) did not finish
   (TOOL OUTPUT). The "which requirements conflict / is relaxing one enough" answer below is MY hand analysis
   plus fixed-design runs of the stand, not a stand verdict over the whole box.

## COULD NOT EXPRESS
1. **The implicit storage balance in the same brick with continuous amounts.** An implicit law (`search` on h) with
   A as a continuous catalog field gives: `BrickError: continuous choices: a requirement or the objective is
   unreadable: unknown quantity or malformed arithmetic: 'implicit(_root_ha, PA__A * _root_ha + Cd * (pi * PL__d *
   PL__d / 4) * sqrt(1.2 * g * _root_ha) * ta - C * ia * Ac * ta, 1 / 100, 12 / 1)'`. The same error with A replaced
   by a plain given, so it is "implicit + any continuous slot", not "implicit + A". BRICKS.md 7/G6 does not say this.
2. **A requirement on the whole set of storms** ("every storm", three at a time) other than one requirement per
   storm; the 8-requirement cap on conflict enumeration then bites (10 here).
3. **Relaxing the site limits as a named requirement** (R5) without widening the catalog by hand and adding
   `PA.A <= 610` as a requirement (I tried the widened form once, see TOOL OUTPUT; it did not complete).
4. A freeboard/limit in a requirement bound that names an amount (`H - 0.30`): refused by the doc, so I made
   `M == PH.H - h` a derived quantity (fine, just indirect).
