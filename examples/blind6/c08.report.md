# c08 report: twin-patient ambulance oxygen bank (problem 8)

Brick: `examples/blind6/c08.json` (one flat brick, `"report": "all"`, 180 designs). Scratch: `work_c08/` (run outputs, my python check `check_c08.py`, a failed modes+totals variant `c08_modes.json`).
Not a chain of devices in the component sense (N couples cylinder, both regulators and conserver through pmin; C couples both regulators, conserver and phases), so I did NOT use components (7d); no flat-vs-component comparison exists. I did try a second flat form (modes + totals, see COULD NOT EXPRESS).

## EXPRESSED FAITHFULLY
- Catalogs as stated: 5 cylinders (Vw, Pn, mass, price), 3 regulators (acc, leak, pmin, price), conserver as an optional slot (`"optional": true`; the stand's `none` item gives kappa = pmin = price = 0), n = 1 or 2 as an integers catalog. 5*2*3*3*2 = 180 designs, all judged.
- Fill factor f in [0.97, 1] (range), so pf = Pn*f; Ta = 263.15 K, Tf = 288.15 K, T0 = 273.15 K, pstd = 1.013 bar as exact givens.
- Z(p) = 1 - 4.8e-4 p + 1.3e-6 p^2 with the decimals written as exact decimals, p/(1 bar) via a given `pu`.
- N law as stated, with real-gas Z at pf (a `define`, toleranced) and at pmin (exact per design).
- Six phase set flows as independent ranges (q1A..q2C); the three phase durations 20/35/40 min as givens with unit min.
- Regulator error e_i = s_i * acc_i with s_i in [-1, 1]; kappa as a range field 0.30..0.40 of the conserver item; leaks as catalog values.
- C law as stated (sum over phases), mass law M = n*mass, R2 as `M <= 16`, objective = total price including 40 EUR manifold when n = 2.
- Units: "checked: every law's dimensions agree" (L, bar, K, min, L/min, EUR, kg).

## APPROXIMATED
1. **R1 as a margin.** A bound may not be a derived quantity, so `N >= 1.2 C` became `margin == N - 12/10*C`, `margin >= 0`. Exact algebra, safe. The checking is the stand's.
2. **pmin = max(...)** is a `computed` value of EXACT catalog fields (nested `max(max(a,b),c)`, because `max` takes two arguments), likewise Zmin, Gmin = pmin/Z(pmin) and the manifold price. Exact per design, so safe; but those are not laws, "nothing in them is judged" - only I and the stand's evaluator vouch for them. If a regulator pmin were toleranced it could not be used.
3. **One e1, e2, kappa for all three phases.** The statement says "e1, e2 the accuracy errors" - read as one error per regulator over the whole mission (a physical regulator), and one kappa per conserver. The worst case is the same if they were per-phase (all terms increase monotonically in e and decrease in kappa), so for the verdict this is safe; the stand can't tell it is the same.
4. **Z(pf) and pf/Z(pf)** are inside the stand's interval reading; no hand algebra. But `how` for `margin` says "outside ZTL: ZTL left it unbounded (a product of toleranced quantities); interval bound by the stand, every corner checked inside". So the bound on the one decisive quantity is the STAND's, not ZTL's. The guaranteed margin range [23.13, 471.8] L of the winner is an outer bound; its true worst case is 29.22 L (my calc). Safe (sound outer), but not tight.
5. Temperatures: Ta etc. entered in K (the doc says C is a difference without offset), so -10 degC was converted by me: 263.15 K. Safe.
6. Fill pressure is not temperature-corrected beyond the problem's own law (Pn is at 15 degC, as the problem states).

## COULD NOT EXPRESS
- **Modes + totals as the natural phase model.** I built it (`work_c08/c08_modes.json`: three modes, `weight` 20/35/40 min, `totals.Ctot`). A requirement on a total needs N on the other side as a bound; a bound is arithmetic over givens and slot.fields only, so `Gmin` (computed) and `max(...)` were refused: "requirement on 'Ctot': 'Gmin' in the bound is not a quantity", then "'max' in the bound is not a quantity". So pmin = max over the fitted devices (a design-dependent exact value) cannot enter a bound, and a total cannot enter a law. Not solved; flat form used.
- A max over three things at once (`max` has two arguments; nested works).
- "Set flow anywhere in the range, independently per phase and patient" and "e per regulator, constant" are both expressed, but there is no way to say that e is constant over time versus per phase; the stand has one reading.
- Nothing needed that the format lacks otherwise; the two requirements, discrete choice, optional part and the nonlinear N were all sayable.

## DOES THE ANSWER LOOK RIGHT
`work_c08/check_c08.py` recomputes all 180 designs in floating point at the worst corner (f = 0.97, all q at their max, s = +1, kappa = 0.30) and takes the verdict by hand.
- All 180 verdicts agree with the stand's (0 differences; 75 EARNED in both). Optimum 625 EUR, same design, same tie.
- Hand number for the winner: N = 1796.40 L, C = 1472.65 L, margin = 29.22 L, mass 14 kg. The stand's guaranteed lower margin 23.13 is below that, as an outer bound should be (consistent, not tight).
- Witness check: stand says CY10/RA/RA/none misses by ~126.6 L; my margin -126.60. I compared three witnesses digit by digit (126.6, 66.3, 68.4: match); the other witness values were not compared, only the 180 verdicts.
- The closest failing design (margin -8.1 L: CY10, RB/RB, none, and CY5 x2) is 8 L short, so the verdicts are not decided by rounding.
- Not checked: ZTL's internal certificate; that "0 differences" rests on my floating-point corner model, which assumes monotonicity (N increasing in pf, C monotone in each datum) - I argued it by hand, did not prove it. My reading of the problem (items 3, 6 above) was shared by stand and me, so it is not independently checked.

## DOC GAPS
- BRICKS.md says bound expressions allow "numbers, given quantities and slot.fields" but does not say that `computed` values and functions (`max`, `exp`...) are NOT allowed there; I found out by the error. Also `computed` accepts only 2-argument `max`/`min`; the error message lists the signatures, the doc does not.
- A `computed` value with a unit needs a unit-bearing name in its expression (EUR from a bare number is an error); the doc only says "declare its unit".
- The doc's skeleton shows `"stand": "ztl-stand/1"`; the example tasks use `"universal-stand/1"`. I used the first and it was accepted.
- `designs_not_listed` / the failed-at-nominal count: the doc explains the first only; "failed_at_nominal" in the output is not defined in the doc (90 here: nominal-failing designs are still listed and judged as REFUTED).
