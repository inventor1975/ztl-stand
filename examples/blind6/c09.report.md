# c09 report: Securing a machine on a flatbed, straps + mat (problem 9)

Files: `c09.json` = the decision brick (min price over 99 designs). `work_c09/c09_find.json` = the same brick plus `find` (largest mass). `work_c09/gen.py` generates both; `work_c09/chk.py` is my own corner check.
`find` replaces the searched quantity's range, so the min-price question (m up to 8400) and the limit question (m up to a) could not be one brick; two files.

Verdict (decision, `c09.json`): EARNED, optimal (every cheaper design REFUTED): strap S2 (LC 2500, STF 450), n = 9, mat M1 rubber, 9*19 + 140 = **311 EUR**.
Verdict (limit, `c09_find.json`): EARNED, largest cargo mass **26832 kg** (26833 REFUTED with a concrete point). Design at that limit: S3, n = 10, M2, 640 EUR.

## EXPRESSED FAITHFULLY
- Three catalogs: 3 straps (LC, STF, price), integers n = 0..10, 3 mats with mu as a RANGE (any value in it). 99 designs.
- m = 7600..8400, alpha = 62..75 deg, f = 0.85..1.15 (actual/nominal pre-tension), kf = 0.85..1.00: all independent givens (ranges).
- Fv = f * STF * sin(alpha) * (1 + kf) as a law. sin(alpha) written as `tan(al)/sqrt(1 + tan(al)*tan(al))` in a `define`, because `sin` does not exist; exact identity for 0 < alpha < 90 deg.
- Three hold margins, one per direction (c = 0.80, 0.50, 0.50), each required >= 0, with g = 9.81 as a given and the 0.8 vertical factor.
- R2 as a requirement on the catalog field `NS.N <= 10`; R3 as `f*STF <= LC/2` (bound is the slot.field expression).
- Objective n*price_strap + price_mat. daN written as unit `10N` (daN is not a known unit); values are the problem's numbers, in daN.

## APPROXIMATED
1. **Margins divided by m*g (hand algebra).** Problem form: mu(0.8 m g + n Fv) >= c m g. I wrote `Mfwd == mu*(0.8 + n*Fv/(m*g)) - 0.8` (dimensionless), equivalent for m > 0. Safe (exact equivalence), but nobody checks the equivalence except me. Reason: the literal form was too slow (see TOOL OUTPUT): m occurs twice and the certificate search chokes near the boundary. The literal form EARNED the same design (311 EUR, 25 s) but could not do the find.
2. **R2 is a tautology.** The catalog already stops at n = 10, so `NS.N <= 10` can never fail. Faithful to the statement, no content. (A catalog 0..12 would make R2 do work, but that is not the stated choice range.)
3. **Price objective is nominal**, which is exact here (prices are exact numbers) - no approximation.
4. **find precision 1 kg**, search range 7600..40000 (my choice). The reported limit is a grid value: true limit is 26832.23 (own calc); the stand says 26832 holds, 26833 fails. Correct to the grid.
5. For the find, "any admissible design exists" is read as "some design EARNED on the whole range [7600, a]" (that is the stand's find semantics with slots); price plays no role there (the objective is only used to order designs). I think that is the same thing as the question asked.
6. In an exploration run only (not the final), I pinned n = 10 with `where`; the final find runs all 99 designs, no pre-selection.

## COULD NOT EXPRESS
- Min-price answer and the limit mass in ONE brick: find replaces the range of m, so the "at 8400" decision and the "largest m" are separate runs.
- `sin` directly (worked around with tan/sqrt, which makes Fv's reported range loose; see DOES THE ANSWER LOOK RIGHT).
- A true "number of straps" semantic: n is a catalog integer, fine; but no way to say the unit daN directly (10N trick works).
- Nothing about the physics itself was inexpressible; no coupling was dropped. Note the strap pre-tension f is ONE draw for all n straps (identical for each strap, as I wrote it), where reality could vary per strap; the problem statement says "actual pre-tension" singular, so I kept one.

## DOES THE ANSWER LOOK RIGHT
My own python (`work_c09/chk.py`): worst case over all 2^5 corners of (mu, m, f, alpha, kf), the literal-form margin is affine in each variable separately and sin is monotone on 62..75 deg, so corners suffice, all 99 designs, R1 + R3, cheapest passing:
- 311 (S2, 9, M1), then 330 (S2, 10, M1), 332 (S1, 6, M2), 344, 355: matches the stand's winner and its optimal flag (25 designs pass in total by my count; the stand stops at the first).
- Worst forward margin of the winner: 1262 N by my corner (0.01531 normalised); the stand's lower end is 0 (the certificate proves >= 0, not the true min), consistent.
- Limit: bisection on the corners of S3/10/M2: 26832.227 kg; the stand's 26832 EARNED / 26833 REFUTED. Matches. I also confirmed that S3/n=10/M2 is the best design for this limit by scanning all 99 designs in python.
- The stand's guaranteed UPPER ranges are loose (Mfwd upper 1.143 vs true max 0.504; Fv upper 18134 N vs true 9998 N). Cause: tan(al) appears twice in sin(al), so its interval reading is wide. It does not matter for ">= 0" requirements (sound), but a user reading `guaranteed` ranges would be misled. The lower end of Mrear (0.147) is also below the true min 0.315: sound but wide. Not checked: R3 by hand beyond the trivial 1.15*650 = 747.5 <= 2500 (S3), 517.5 <= 1250 (S2), 402.5 <= 750 (S1), all pass. I did not check the stand's refutation of cheaper designs one by one beyond comparing the winner against my list.

## DOC GAPS
- BRICKS.md does not say that a divisor-free form is much better for the certificate search: the same law written with m twice cost 25 s (main) and made `find` impossible (>900 s), while the m-once form took 8.8 s / 3 min. A hint "write each toleranced quantity once, divide through" would have saved most of this work.
- `daN` and `kN` style units: `N` is listed with prefix k, but `da` is not; the doc does not say how to write decanewton (the `10N` trick comes from the line "a number may stand in a unit"). 
- The doc says "`find` ... With slots, 'works' means some design works on the whole range", but not that the whole slot catalog is re-judged on every try, so a find over a big catalog costs tries x full run, and a near-boundary try can be far slower than the rest (832 s for one).
- `sin` and `cos` missing is documented; the tan/sqrt workaround and its loose `guaranteed` ranges are not.
- The "stopped" output on a time kill (OPEN, stopped_at, bracket so far) is not in the doc; useful, but the doc only says OPEN means undecided.
