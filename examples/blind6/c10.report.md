# c10 report: maize batch dryer + silo aeration fan, Td and Mf continuous (problem 10)

Files: `c10.json` (one flat brick, all 16 dryer x fan combinations, Td and Mf continuous); scratch in `work_c10/`
(single-dryer variants `*_allfan.json`, the 4-combination repro `k_dr610_nf15.json`, pinned checks `pin1.json`,
`pin2_dr8.json`, my python `chk.py`, `verify.py`, outputs `*.out`).

**Headline: the stand's answer for the brick as written is WRONG (a false EARNED with a mislabelled design). The
correct optimum, got by splitting the same brick per dryer, is DR8 + no fan, Td = 65.784 C, Mf = 0.17679, 51.669 kEUR.**

## EXPRESSED FAITHFULLY
- All uncertain data as independent ranges: M0, k0f, n (as `nP`), RH0, T0, Ta.
- Dryer (4 listed items: B, Tmax, price), fan (4 listed items incl. "none": qa, price), Td and Mf as two continuous
  slots (Td 50..85 C, Mf 0.14..0.20).
- Every law as printed, as definitions `X == expression`: RHd, Me, MR, Page rate k, t (with the non-constant exponent
  1/n), Q = B/(t+1), DI, Ts (with `max`), Mwb, ST.
- R1, R2, R3 as requirements on Q, DI, ST. R4 as a requirement on the catalog field `TD.x <= DRY.Tmax` (bound naming
  an exact value of the combination, accepted).
- Objective: dryer + fan + 900 t * W * 0.09 * (1 + 0.012 (Td-60)), W with M0c = 0.36 as a separate given (the
  problem says use the worst-case M0 for the cost). Fixed (not nominal-data) objective, so "worst-case cost" = cost.
- Units checked ("every law's dimensions agree"): temperatures as `C` divided by a given `Tu = 1 C`, hours via `Hu`.

## APPROXIMATED
- `1/1.8634` written as `5000/9317` (exact), `8.6541e-5` as `(86541/1000000000)` (see DOC GAPS). Exact, safe.
- Td range is the union [50, 85]; R4 enforces the per-dryer maximum. Exact, checked by the stand.
- `k` kept as a dimensionless number in 1/h^n (`kk`), `t = Hu * (...)^(1/n)`. A unit bookkeeping choice, no value change.
- "Worst case" for the cost = M0c = 0.36 as the problem states. Nothing else changed.
- Nothing was bounded or rounded outside the stand. No hand algebra, no bands. Td and Mf are not gridded: the
  continuous solver handles them (nonlinear in the amounts, so the "not affine" path with zmin).
- Components (7d) not used: Td and Mf are continuous choices that feed both the dryer and the silo, and a
  continuous parameter inside a component does not exist yet (BRICKS.md 7d). I did not try a flat-vs-components
  comparison. Flat only.

## COULD NOT EXPRESS
- A per-dryer range for Td (Td <= Tmax) inside the slot: only the requirement R4 (works, but the solver searches the
  whole 50..85 range for every dryer).
- Nothing else in the problem was blocked. The one tool-side loss is the false result below, not a format gap.

## DOES THE ANSWER LOOK RIGHT
My own python (`chk.py`, `verify.py`; worst case taken at the 32 corners of M0, k0f, n, RH0, T0 for t, at the Ta
corners for ST; grid of 0.01 C in Td, bisection in Mf):
- Optimum per dryer, no fan: DR8 51.6698 (Td 65.79, Mf 0.176791), DR10 57.0675 (Td 61.19), DR6 and DR4 infeasible
  without a fan. DR6 + F25: 52.0283 (Td 70.05, Mf 0.18727). The stand's 51.669 / 65.784 / 0.176791, 57.0669 / 61.185
  and 52.0274 / 70.043 / 0.18727 agree (the stand's values are the slightly better continuous optimum).
- Hand reasoning: Mf is capped by R3: no fan means Ts = 22 at Ta = 16, so Mwb <= 15.02, Mf <= 0.17679. A fan buys
  only 0.004..0.010 of Mf (about 0.25..0.62 kEUR of drying energy) against 2.4..7.5 kEUR, so no fan wins unless
  the dryer needs it (DR6 does: its time limit is too tight at Mf = 0.1768).
- Td is set where R1 meets the cost slope (cost rises with Td at ~0.033 kEUR/C): DR8 needs t <= 9 h at the worst
  data point, which is exactly where Q = 0.8 binds (my python: t = 8.99999, Q = 0.8000001). DI = 0.572 there <= 0.6
  (the stand prints DI <= 0.6, a proved enclosure, not the tight value).
- Not checked: that the worst data point is always a corner (I assumed monotone; the stand's certificate covers it
  for the DR8 design and the pinned design confirms it). I did not run `--dev` (the command was fixed).
- Answer to the question: dryer DR8, no fan, Td = 65.78 C, Mf = 0.1768 (wet basis 15.02 %), cost about 51.67 kEUR.
  Not what the full c10.json prints.

## DOC GAPS
- `0.000086541`: the brick error `unknown quantity or malformed arithmetic: '8.6541e'` - a decimal written in a law
  is apparently turned into a float string with an exponent and re-read. Small decimals with a leading-zero run
  should be written as fractions. Not in BRICKS.md.
- BRICKS.md section 2 does not say that a negative `gap` (lower bound above the cost found) means something is wrong, nor
  that a design in the printout must be the one the mix was judged on. `optimal: true` was printed with gap -0.34.
- A requirement directly on a continuous field (`TD.x <= DRY.Tmax`) is allowed ("a requirement may name a catalog
  field") but the continuous section does not say so; it worked.
- The `stand` tag: examples use both `ztl-stand/1` and `universal-stand/1`; both seemed accepted.
- Section 7d's "Not yet: a continuous parameter inside a component" decides here that the chain cannot be built from
  components; the doc has no word on a system with continuous system-level choices.
