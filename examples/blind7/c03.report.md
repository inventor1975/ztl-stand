# c03 report: Two ice-cream trucks of different lives, EAA worst case (problem 03)

## EXPRESSED FAITHFULLY
- c03.json: one slot T choosing between the two trucks (catalog items "Older, larger" and "Newer, smaller"): price 50000 USD (exact), life n = 3 / 6 (exact), inflow as a range [38000, 42000] / [28500, 31500] USD (independent per truck, as the catalog range is a separate box per design).
- r: one given quantity, range [0.09, 0.11], shared by NPV and EAA of the chosen truck.
- Laws: NPV == -price + inflow*(1 - (1+r)^-n)/r and EAA == NPV*r/(1 - (1+r)^-n), as stated.
- Requirement: EAA >= 17000. Objective: minimize -EAA, case worst (buy the best worst-case EAA). report: all, so both trucks are judged.
- Question "each truck's worst-case EAA": c03b.json (older only) and c03c.json (newer only), each with find largest L such that EAA >= L (L given, requirement bound = L), from 0 to 40000, precision 0.01.

## APPROXIMATED
- The sum over k=1..n is written as its closed-form geometric sum (1-(1+r)^-n)/r. This is exact algebra, not an approximation. Nobody in the stand checked it against an explicit sum; I did (check.py uses the explicit sum, exact Fractions).
- find reports a grid value (precision 0.01), so the worst-case EAAs are known to within 0.01 USD.
- The objective's reported value for the older truck is -17000 (the requirement bound, an upper bound proved), not its true worst case; true worst cases come from the find bricks.
