# c08 report: Capacitor bank for power-factor correction (problem 08)

## EXPRESSED FAITHFULLY
- P in [380,420] kW, pf in [0.75,0.79], delivered fraction dl in [0.95,1.05]: three independent ranges.
- Tariff 3.00 USD/kVA/month as an exact given; the seven banks (kvar, cost) as a listed catalog in one slot.
- Laws: Q = P*tan(arccos(pf)); kVA0 = sqrt(P^2+Q^2); Qnet = Q - dl*bank kvar; kVA1 = sqrt(P^2+Qnet^2);
  pfc = P/kVA1; save = 3*(kVA0-kVA1); payback = cost/save.
- Requirements: pfc >= 0.95 and payback <= 32 (worst case, as the stand judges for all values). Objective: minimize bank cost.
  `report: all` so every bank gets a verdict.

## APPROXIMATED
- tan(arccos(pf)) written as sqrt(1-pf*pf)/pf (no acos in the format). It is an exact identity for pf in (0,1], so safe;
  checked by me (my script uses math.tan(math.acos())).
- "Month" is not a unit: the tariff is declared as USD/kVA and saving as USD, with "per month" only in the labels; payback is then
  a plain number of months. Unit check cannot see the month; nobody checked it but it is by construction.
- Per-bank worst-case numbers (not in the main output): obtained from 14 auxiliary `find` bricks (work_c08/f_*.json), one bank
  pinned each, searching the largest pf floor T and the smallest payback cap L. For payback the requirement was written
  `save >= C.cost/L` (equivalent for save > 0) because the `payback == cost/save` law came out OPEN for b100 (interval reading
  of save contains zero). Values are on a grid (0.0001 for pf, 0.001 for payback). Checked by the stand's own proofs and by my scan.

## COULD NOT EXPRESS
- The main brick reports, per bank, only a verdict (and for the earned bank guaranteed ranges whose end equals the requirement's bound);
  it does not print each bank's exact worst-case pf and payback. I got these via the `find` bricks above.
- A unit for "month".
